# ORDER v7  (mode: normal)

## 目的
こだまを「確実に目に見える・気持ちよい」ものにして、触った結果が戻ってくる体験を静止画でも伝わる形にする（あわせて波の質感と差分の清潔さを整える）。

## 現状（司令塔の評価: 6/10、ヘルス OK）
- v6 のこだまは内部では動く（`dataset.echoes` が増える）が、司令塔の `probe`（mobile, `/?live=1`、タップ後 6.5 秒・12 秒）では**画面にほぼ何も写らなかった**。原因は、こだまの見た目が「460ms の flash（`main.js` の `flash()`）」と、低 fps で伸びきらない波紋だけで、**視覚的な手がかりが一瞬で消える**ため。
- 良くなった点: ちぎれ弧の筋は `desktop-calm-after.png` で消えた。微粒子も適度。
- 制約は維持: **新規シェーダーパス禁止、常時 rAF 化禁止（`wake()` 維持）、CSS アニメは `transform`/`opacity` のみ**。

## やること（優先順）
1. **こだまの「戻りの光輪」（CSS のみ、新規コード小）**
   - `echo.js` の再生時（`main.js` の `createEcho` の `play`）に、**元のタップ位置**へ、波シミュレーションとは独立した CSS の光輪要素（例 `.echo-ring`）を 1 つ出す。内容: 細い 1px 前後の円縁（`border` もしくは `radial-gradient`、アクセント色・低不透明度）＋その内側のごく淡い光の芯。
   - アニメーションは `transform: scale()` と `opacity` のみ。**約 2.4〜3.2 秒**かけて、小さく出て→ゆっくり広がり→消える（`cubic-bezier(.2,.8,.2,1)`、2 回目のこだまは一回り小さく・淡く、持続はやや長め）。これにより、波紋の fps に依存せず静止画に必ず写る時間幅ができる。
   - 既存の 460ms の `flash` は、こだまでは使わない（光輪に置き換え）。タップ直後の通常の `flash` は変更しない。
   - 要素は完了時に必ず `remove()` する。同時に存在する光輪は最大 8 個（超えたら古いものを即 `remove`）。`prefers-reduced-motion` では透明度のフェードのみ（`scale` は固定）でよい。
   - 波紋側（`ripple`）の amp は、v6 の 0.6/0.36 から **0.75/0.45** に上げる。ただし元のタップより明確に弱いこと。
   - 受け入れ条件: `probe` で `/?live=1`、mobile、`clickAt [195,420]` → 5.8〜6.8 秒の間に撮った `shot` に、(195,420) 付近へ光輪が写る。6 秒時点と 7.5 秒時点のどちらかで必ず見えるようにすること（持続時間 2.4 秒以上のため）。`dataset.echoes` は従来どおり増える。コンソールエラー 0。
2. **タップ直後の波紋の質感を整える（定数の調整のみ）**
   - 現状の `desktop-touched.png` は、芯の光と外側の輪の間が暗く抜け、「ドーナツ」状に見える。輪の内側が自然に明るく滑らかにつながるよう、リム光・芯の光のグラデの幅や強さ（`wave-gl.js` のシェーダー内の定数、`flash` の radial-gradient の止め位置）を調整する。新パス・解像度変更なし。
   - 受け入れ条件: `desktop-touched.png` / `mobile-touched.png` で、芯から輪へ向けて明るさが連続し、輪の縁が 1 本の滑らかな線に見える。夜・暁でも破綻しない（`mood-night` / `mood-dawn`）。調整が逆効果なら元に戻し、その旨を REPORT に書く。
3. **行末（CRLF/LF）の統一**
   - v6 の diff は、`main.js` / `wave-gl.js` / `index.html` / `shots.json` が全行書き換わっており、実質の変更が追えない。`app/` 内の編集ファイルは、**ファイルの元の行末を保つ**（変換しない）こと。今回触るファイルで、行末が混在・変換されていないか確認し、REPORT に書く。
   - 受け入れ条件: 今回の `diff.stat.txt` の変更行数が、実際に編集した量と同程度（数十行規模）であること。

## やらないこと
- マイク入力、ポインタ追従、媒質切替、録音/再生 UI、新ボタン、説明文の追加。
- 新規シェーダーパス、解像度引き上げ、常時 rAF ループ化、外部ライブラリ追加。
- こだまの回数・間隔の変更や設定 UI（5.5 秒・11 秒のまま）。
- ムード追加、バーの変更、「響」の変更。

## 見た目・UX の要求
- デスクトップ 1280×800: こだまの光輪は元のタップの輪より細く淡く、優雅に広がって消える。元の演奏を邪魔しない。重なっても濁らない。
- スマホ 390×844: 光輪がバー領域に重なっても、バーの操作や見た目を邪魔しない（`pointer-events: none`、バーより下の z-index）。タップ 44px 以上、配置は変えない。
- 説明文は増やさない。「触れた場所が数秒後にそっと戻る」ことが、文字なしで伝わること。

## デモモード
- `?demo=1`: 幽霊の指の演奏も従来どおり記録され、起動 6〜9 秒で光輪が写る。`shots.json` の既存 7 シーン（`echo` 含む）は維持。`echo` の待機は、光輪が確実に写る時間（こだま再生の 0.5〜1.5 秒後）に合わせてよい。
- 非デモ: `/?live=1`。タップ→約 6 秒で光輪。

## 作業役への注意
- 変更後に必ず `npm run build`、`?demo=1` と `/?live=1` の各 15 秒放置で rAF が止まるか（`live` は止まること）を確認し REPORT に書く。
- REPORT には、スクショで確認した事実と、測れなかったことを分けて書く。光輪が撮れたタイミング（タップ後何秒）を数字で書く。
- 受け入れ条件を `probe` で自分で確かめ、撮れなかった場合は正直に書く（司令塔は同じ手順で確かめる）。
- コミットに Claude を貢献者として入れない。`comms/VISION.md` と `comms/STATE.json` は触らない。
