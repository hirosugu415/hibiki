# ORDER v41  (mode: normal)
## 目的
案B「水面の残像」を実装し、アプリを閉じて開き直したとき、前回の水面の淡い記憶が水底に浮かび、最初の一打で静かに洗われる再訪体験を足す。

## やること
1. **残像の保存**: 最後の打から約4秒静止（calm）した時点で、水面の「絵」を 48px 幅程度の小さな画像（または、打の位置・時刻・ムードから生成した数個の光点）として `localStorage['hibiki.afterimage']`（数KB以下、try/catch 必須）に保存。GL キャンバス読み出しが空・真っ黒になる場合は、生成した光点版を使う（退路。先に確認し、安全な方を選ぶ）。
   - 受け入れ条件: 打って4秒静止後に `document.body.dataset.afterimage = "saved"`。localStorage にキーが存在。保存中にフレーム落ちやコンソールエラーなし。
2. **再訪時の表示**: 起動時に保存があれば、背景（水・オーラ層）の下に blur 18px 以上・不透明度 0.14〜0.22 で淡く表示（`dataset.afterimage = "shown"`）。最初の `tap()` から約2.5秒で opacity 0 に消え、以後は破棄（`"washed"`）。保存が無ければ `"none"` で現状と同一。
   - 受け入れ条件: 静止画2枚（desktop・mobile）= 再訪直後（水底に前回の淡い光が見える。石・「触れてみてください」・バー・「響」の見え方と階層は現状と同じ）と、タップ2.8秒後（残像は消え通常の水面）。2 枚の並置で差が分かるが、「汚れ」や「ゴミ」に見えない。
3. **デモ/評価用**: `?demo=1&seed=1` では、保存が無くても決定的な残像を即表示（幽霊の一幕の終端を同じ保存経路に通す、または固定の生成絵を使う）。クエリは評価専用で、無ければ通常動作。
   - probe 例: `[{"goto":"/?demo=1&seed=1"},{"wait":600},{"shot":"after-0"},{"clickAt":[820,420]},{"wait":2800},{"shot":"after-1"},{"eval":"document.body.dataset.afterimage"}]`
4. `app/shots.json` に再訪直後（`afterimage-shown`）とタップ後（`afterimage-washed`）の2枚を desktop・mobile 向けに追加。

## やらないこと
- 砂（輝度・強度・形状・距離基準）に一切触らない。バーや UI 要素の追加、文字の追加、ダウンロード/共有ボタン、外部送信、ライブラリ追加。
- 残像を主役にしない（不透明度は 0.22 を超えない）。手紙・器との機能重複を作らない。

## 見た目・UX の要求
- desktop・mobile 共通: 残像は blur 大・低コントラスト・ムード色に馴染ませ、水の一部に見えること。初回表示の「何をすればいいか」が揺らがないこと。洗われる動きは 2.5 秒前後のなめらかなフェード（ちらつき・急な消失なし）。
- 初回（保存なし）の home と3秒ルールは c39 と完全に同一。

## デモモード
`?demo=1&seed=1` で再訪状態を再現。通常の `?demo=1` では保存が行われ、同じブラウザコンテキストで 2 回目の goto すると `shown` になることも確認する。カメラ・マイク不要。

## 作業役への注意
- 最大リスクは「汚れに見える」こと。出来上がりの静止画を自分で見て、美しくなければ不透明度を下げるか blur を上げる。
- GL キャンバスの toDataURL は描画直後でないと空になる。確認して、駄目なら生成絵に切り替える。
- localStorage の読み書きは必ず try/catch。壊れた値は無視して `none` に。コンソールエラー 0 を厳守。
- 1サイクルで終わる量に絞り、NOTES.md を更新して REPORT に変更ファイルを列挙すること。
