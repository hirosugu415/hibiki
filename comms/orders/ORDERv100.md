# ORDER v100  (mode: innovation)
## 目的
実装はせず、「響」に足せる他のアプリにない新機能案を3つ `comms/IDEAS.md` の末尾に提案する（見出し: `## Cycle 100 — 提案 (builder)`）。

## やること
1. `app/NOTES.md` と IDEAS.md の末尾（c96 の決定まで）を読み、既出の案（跳ね返る雫・隣の窓・張る・凪の一音・出会いの音・指の腹 等）と重複しない3案を書く。
2. 発想の領域（いずれも「触れる → 音と光の波になる」の核を壊さないこと）:
   - **残すこと・持ち帰ること**: 弾いた演奏の痕を、静かな形（画像・短いリンク・一枚の絵）として持ち帰る・送る体験。localStorage のみ、外部送信なし。
   - **世界観の切り替え**: 水以外の媒質（墨・絹・砂 など）を、1タップで質感ごと変える方法。既存の媒質機能と被らない切り口。
   - **スマホ幅の親指1本**で完結する新しい弾き方（デモモードで再現できるもの）。
3. 各案に必ず書く: 名前 / 体験の一文 / 何が新しいか / 実装規模（S/M/L）/ デモモードでの評価方法（`?demo=1` と shots.json の画面名）/ 最大リスクと撤退条件 / VISION の絶対のルール（初見3秒・説明文なし・Apple 水準）への影響。
4. 最後に「作業役の推し」を1案だけ理由付きで書く。

## やらないこと
app/ のコード変更、UI 追加、ORDER の先取り実装。底の光（caustic、金の輪）や vesselRing の調整案は出さない。既存機能の微調整案も不可。

## 見た目・UX の要求
案ごとに、desktop（1280×800）と mobile（390×844）で静止画として何が見えるかを具体的に書く。文字を増やさず、操作は説明なしで分かること。ホームの静けさは乱さない。

## デモモード
カメラ・マイク・センサーが無くても `?demo=1` の幽霊の指だけで評価できる案に限る。評価のための URL パラメータと shots.json 画面名を案ごとに指定する。

## 作業役への注意
- 書くのは IDEAS.md への追記のみ。既存内容は変更しない。
- NOTES.md は更新不要。REPORT は事実のみ簡潔に。
- 次の c101 は上限のため存在しない可能性がある。案は「最終形に近い、小さく確実に入る」ものを優先する。
