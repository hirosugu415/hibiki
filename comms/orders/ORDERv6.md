# ORDER v6  (mode: normal)

## 目的
「触れた演奏が、数秒後に淡いこだまとして水面に戻ってくる」最小版（IDEAS 案A の縮小版）で**触った結果が残る体験**を作り、あわせて波のちぎれノイズを抑えて核の繊細さを上げる。

## 現状（司令塔の評価: 6/10、ヘルス OK）
- v5 で環境光・微粒子・ヒント位置・「響」・暁のコントラストが整い、初見の空虚さは薄れた（5→6）。
- 残る弱点: ①タップ後 2〜3 秒で水面が空になり、演奏した感触が残らない（`probe` の `mobile-t3.png`）。②`desktop-calm-after.png` 上部に、ちぎれた細い弧の筋があり、波の繊細さを損なう。③微粒子が極小で、非デモ放置時の誘いが弱い。
- 制約は維持: **新規シェーダーパス禁止、常時 rAF 化禁止（`wake()` 維持）、CSS アニメは `transform`/`opacity` のみ**。

## やること（優先順）
1. **こだま（Echo）— 最小版**（新規 `app/src/echo.js` 80 行前後＋`main.js` に数行）
   - ユーザーの `onDown` の `tap()`（および `?demo=1` では幽霊の指の `tap()`）を記録し、**約 5.5 秒後**に同じ位置・同じ音高で、**弱いタップ**として再生する（`ripple` の amp は元の約 55%、`note` の vel は元の約 45%、`flash` は小さく淡く）。さらに **約 11 秒後**にもう一度、もっと弱く（amp 約 30%、vel 約 22%）。それ以上は繰り返さない（積み上がって濁らない）。
   - こだま自身は記録しない（無限ループ禁止）。ドラッグの連続注入（`strokeTo`）は記録しない。保留中のこだまは最大 24 件、超えたら古いものから捨てる。タブ非表示中は再生を見送る。
   - 再生は `setTimeout` で `ripple(..., live=5000)`＋`note()`＋小さな `flash` を呼ぶだけ。再生が終われば `wake()` の期限で rAF は止まる（常時ループにしない）。音は `audio.unlock()` 前は鳴らなくてよいが、波紋は立つこと。
   - `document.body.dataset.echoes` に**累計再生数**、`dataset.echoPending` に保留数を出す。
   - 受け入れ条件: `/?demo=1` を 8 秒待つと `dataset.echoes` が 1 以上。`probe` で最初のタップの後 6 秒待つと、同じ位置に弱い輪が再び立つのが `mobile-*.png` で見える（位置が元のタップと一致）。非デモでも同様。コンソールエラー 0。`prefers-reduced-motion` でも波紋は立ててよい（水面の物理なので）。
2. **波のちぎれ弧・縁の二重リングの調査と抑制**
   - まず原因を特定して REPORT に書く（候補: ドラッグ/幽霊の連続注入が作る不連続、波速が速すぎて格子の分散誤差が出ている、リム光の閾値処理がエッジで途切れる、減衰が弱く反射が重なる）。
   - 追加パス・解像度引き上げなしで、定数（減衰、注入半径、リム光のスムースステップ幅、境界の吸収）の調整で、`desktop-calm-after.png` に出ていた「ちぎれた細い弧」を目立たなくする。大きな輪の縁が二重の細線に見える点も、1 本の滑らかな縁に近づける。
   - 受け入れ条件: 幽霊の指が 20 秒演奏した後の `desktop-calm-after.png` で、ちぎれた弧の筋が見えない（輪は連続し滑らか）。SwiftShader でフレーム時間が悪化しない（`wake` が止まること）。原因が特定できなければ、その旨を正直に REPORT に書き、確実な範囲（減衰の微増など）だけ行う。
3. **微粒子の存在感をわずかに上げる**（CSS のみ）
   - 微粒子のサイズを 1.3〜1.5 倍、不透明度を 1〜2 割上げ、2〜3 個は小さな柔らかい光（ぼかしは静的な `radial-gradient`）にして、`mobile-idle.png` / `mobile-home.png` で気づける程度にする。派手にしない。波紋・ヒント・バーより目立たないこと。要素数は 14 以内を維持。

## やらないこと
- マイク入力、ポインタ追従、媒質切替（案B）、録音/再生 UI・新ボタン・説明文の追加。
- 新規シェーダーパス、解像度引き上げ、常時 rAF ループ化、外部ライブラリ追加。
- こだまの回数・間隔を設定できる UI（固定値でよい）。
- ムード追加、バーの変更。

## 見た目・UX の要求
- デスクトップ 1280×800: こだまの輪は元より明らかに弱く細く、元の演奏を邪魔しない。ちぎれ弧の無い滑らかな輪。
- スマホ 390×844: タップ 44px 以上維持、バー・ヒント・「響」の配置は変えない。こだまの輪がバー領域で不自然に切れない（発生位置はタップ位置のままでよい）。
- 説明文は増やさない。「触れた場所が数秒後にそっと戻る」ことが、文字なしで伝わること。

## デモモード
- `?demo=1`: 幽霊の指の `tap()` を記録対象にし、起動 8〜12 秒で `dataset.echoes` ≥ 1、静止画にこだまの輪が写る。幽霊の演奏と同時に鳴っても汚くならない（こだまの音量は小さく）。
- `shots.json`: 既存 6 シーンを維持。`touched` の後で 6〜7 秒待つ `echo` シーン（デスクトップ/スマホ両方で撮れる形）を 1 つ追加してよい。`/?live=1` の `idle` は維持。

## 作業役への注意
- 変更後に必ず `npm run build`、`?demo=1` と `/` の各 15 秒放置で rAF が止まるか確認し REPORT に書く（v2 の失敗の再発防止）。
- REPORT には、スクショで確認した事実と、測れなかったことを分けて書く。ちぎれ弧の原因が分からなければ分からないと書く。
- ORDER にない `shots.json` の url 変更など逸脱をした場合は理由を明記する。
- コミットに Claude を貢献者として入れない。`comms/VISION.md` と `comms/STATE.json` は触らない。
