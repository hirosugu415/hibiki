# ORDER v57  (mode: normal)
## 目的
案A「刻の水」を実装する。端末の実時刻（または `?hour=`）で、水の上端の空の色・残響の長さ・音階の中心が連続的に移り、開く時刻で別の水になる。

## やること
1. **時刻 → tint の関数**（`moods.js` 周辺）。`hour`（0–24、小数可）から連続的に tint を出す。朝(6)=冷たい青灰、昼(13)=現状と同じ（中立）、夕(19)=琥珀寄り、夜(1)=深く暗い青。ムード（凪/夜/暁）は型として残し、その上に加算するだけ（置き換えない）。
   受け入れ条件: `?demo=1&seed=1&hour=13` の home が現状（c56）と見た目ほぼ同一（回帰ゼロ）。`hour=6` と `hour=19` の desktop-home で上端 20% の色相が明確に違う（朝=青灰 / 夕=琥珀寄り）。中央〜下の輝度差は ±3% 以内。
2. **反映先は 3 つだけ**: (a) 上端の空色（既存 `uSky` の色に加算、強さ上限 8%）、(b) 残響の長さ（夜 +、昼 −、±15%）、(c) 音階の中心（夜はやや低く、半音〜2 半音以内）。新しいパス・UI・文字は追加しない。
   受け入れ条件: 3 つが `dataset.hour="時刻,tint,reverbK"` に出て、hour=6 / 13 / 19 / 1 で値が別。
3. **`?hour=` と時刻未指定**: 指定時はそれで固定。未指定は実時刻（`new Date()`）で 1 回決めて、分単位では変えない（セッション中は 60 秒に 1 回ゆっくり補間でよい）。
   受け入れ条件: `?hour=` が不正値のとき実時刻にフォールバックし、コンソールエラー 0。
4. **`app/shots.json`**: 既存の撮影はすべて `hour=13` を付けて固定（比較の基準を守る）。追加で `hour-morning`(6)、`hour-evening`(19)、`hour-night`(1) の desktop/mobile 6 枚。
5. NOTES.md に追記（tint の関数、dataset.hour、`?hour=`）。

## やらないこと
- 唸り（案B）、干渉の肖像（案C）。新しい UI・ボタン・文字。ムードの置き換えや新ムード追加。
- 中央〜下の背景を明るくすること（c51 の「背景持ち上がり」の再発）。
- 外部通信、位置情報、天気 API。

## 見た目・UX の要求
- desktop: 夕の上端にだけ琥珀がかすかに差し、全体は静か。朝は冷たく淡い。色が濁らない（ムードとの二重掛けで灰みが出ないこと）。
- mobile: 同じ。上端 20%（短辺比）の帯が不自然な線に見えない（なだらかな勾配）。
- 3 秒体験（最初のタップで波紋と音）は不変。

## デモモード
- `?demo=1&seed=1&hour=6` / `hour=19` / `hour=1` / `hour=13`。幽霊の指が打つ音の残響差は dataset の reverbK で確認する。

## 作業役への注意
- 加算量は小さく固定。夜ムード × 夜の時刻のように重なる場合は合計に上限（上端 +8%、輝度 ±3%）をかける。
- hour 指定なしの既定撮影が時刻でぶれないよう、shots.json は必ず hour を固定する。
- 見た目が変わらない（差が識別不能）なら失敗。上端 20% で hour=6 と 19 を並べて、明確に違うことをスクショ 2 枚と REPORT の数値で示すこと。
