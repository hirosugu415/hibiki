# ORDER v10  (mode: normal)

## 目的
「触れ続けると水面が深くなる」最初の遊び（長押しの泉）を最小版で足し、あわせて光の輪を太い霞んだ帯から髪の毛のように細い精緻な輪へ整える。

## 現状（司令塔の評価: 6/10 横ばい、ヘルス OK、v9 コミット済み）
- v9 で泡状の円盤は解消（`.flash` 0 本、`desktop-calm-after.png` の (830,335) は輪＋小さな芯）。
- 残る弱点（証拠）:
  - `shots/cycle-009/probe/desktop-c-300.png`: 輪が太く霞んだネオン管状で、2 つの輪が重なる所が濁る。外側に暗いリムが付いて太さを増している。
  - `desktop-c-800.png`（打鍵後 0.8 秒）: ほぼ何も残らず、余韻が見えない。
  - 「触る→鳴る→消える」の 1 層だけで、遊びが深くならない（6 点で 5 サイクル横ばい）。

## やること
1. **長押しの泉（案A 最小版）** — 指/ポインタを 260ms 以上押し続けると、その点が「泉」になる。
   - 押している間、同じ点から輪が一定間隔で湧き続ける（既存の `splat()` を使う。1 秒あたり約 3〜4 回、1 回の振幅は単発の約 0.4 倍。追加パス・解像度引き上げ禁止、押している間だけ `wake()` で rAF を維持）。
   - 音は伸びる: `audio.js` に持続版の声（`voiceHold`）を足す。サステイン（振幅エンベロープを保つ）＋ 5Hz・±0.3% 程度の弱いビブラート。離す（`pointerup` / `pointercancel` / `blur` / `visibilitychange`）と 0.6 秒で必ず減衰して止まる。同時 12 声の上限内、止め忘れ禁止。
   - 指を動かしたら泉は指に付いてくる（既存の `strokeTo` の挙動を壊さない。動かさない時だけ泉になる）。
   - UI の追加はゼロ。バー・ヒント・「響」は変えない。短いタップの挙動は完全に従来どおり（260ms 未満は何も変わらない）。
   - 受け入れ: `document.body.dataset.holding` が `"0"`→`"1"`→`"0"` と変わり、保持中は `dataset.holdHz`（持続音の周波数）が出る。`?demo=1` の幽霊の指が、モチーフの合間に約 3 秒の長押しを 1 回行う（`ghost.js` に `hold(x,y,ms)` を追加）。起動 4〜8 秒の間に撮ったスクショで、1 つの点を中心に**間隔の揃った複数の同心円**が見える。低音側(x<0.25)と高音側(x>0.75)で輪の間隔が違うこと（低音＝ゆったり、高音＝細かく）。
2. **輪を細く精緻にする（`wave-gl.js` RENDER の定数中心）** — 1 変数ずつ調整。
   - `EDGE_W` を狭くして線を細く、暗いリム（影）を弱めて、輪が「髪の毛のように細い明るい線＋ごく弱い影」に見えるようにする。2 つの輪が重なっても濁らないこと。
   - 受け入れ: `?demo=1` 1 秒待ち→(500,400) クリック→300ms 後の probe スクショで、輪の明るい線の太さが v9 の約半分以下で、重なり部が帯状に濁らない（デスクトップ・スマホ両方）。
3. **波の余韻を少し長く** — 波の減衰（`uDamp` 周り、物理式そのものは変えず定数のみ）を緩め、打鍵後 1.5 秒の時点でも輪が薄く見えるようにする。ただし反射で画面が荒れない・白飛びしない範囲で。
   - 受け入れ: 打鍵後 1.5 秒の probe スクショに、薄い輪が残る。

## やらないこと
- 保存・書き出し・新しい UI・バーへの追加（案B・他は今回やらない）。
- 追加シェーダーパス、解像度引き上げ、常時 rAF、テクスチャ読み取り数の増加。
- 複数指同時の泉、速度による音色変化（次以降）。
- 波の物理式（h, v の更新式）の変更、`flash()` の復活、こだま光輪の作り替え。
- 項目 2・3 で調整が収束しない場合は、元の定数に戻して REPORT に記す（足さずに戻す）。

## 見た目・UX の要求
- デスクトップ 1280×800・スマホ 390×844 の両方で、長押し中の泉が「水面に湧く光の輪」に見えること（UI 部品に見えない）。白飛びしない（`knee` 維持）。
- スマホ幅で、長押し中に画面スクロール・ページ拡大・コンテキストメニューが出ないこと（`touch-action: none` 等を確認）。
- 凪・夜・暁の 3 ムードで輪の色がアクセントに従う（維持）。
- 3 秒ルール不変: 開いて 1 タップで輪と音が出る。長押しは説明文なしの「発見」にする（ヒントの文言は変えない）。

## デモモード
`?demo=1` の幽霊の指だけで確認できること。`shots.json` に、泉の撮影用に画面を 1 つ足してよい（例: `{"name":"hold","url":"/?demo=1","steps":[{"wait":5500}]}`。幽霊の長押しのタイミングに合わせて調整し、REPORT に書く）。既存の 7 画面はそのまま維持。`?fallback=1`（Canvas2D）でもコンソールエラーが出ないこと（泉は WebGL2 のときだけ視覚が出れば可、音は両方で鳴ってよい）。ヘッドレスは描画が遅いので、タイミングは余裕を持たせる。

## 作業役への注意
- 失敗の再発防止: 持続音の止め忘れを必ず塞ぐ（`pointerup` / `pointercancel` / `blur` / `visibilitychange` / 要素離脱）。probe で長押し後に離して、`dataset.holding === "0"` になることを確認。
- v2 の教訓: 変更前後で rAF 間隔（60 フレーム平均）を測って REPORT に書く。通常時（長押しなし）は v9 比 +10% 以内。
- 項目 1 を最優先。時間が足りなければ 2・3 は定数 2〜3 個の調整だけで止めてよい。
- 係数調整は 1 変数ずつ。輪が崩れる・ちらつく・白飛びしたら戻す。
- コミットに Claude を貢献者として入れない。`comms/VISION.md` と `comms/STATE.json` は触らない。
- REPORT には、長押し中のスクショ名、`dataset.holding`/`holdHz` の eval 結果、`.flash` 本数、rAF の before/after を必ず書く。
