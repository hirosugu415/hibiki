# ORDER v13  (mode: normal)

## 目的
水面に「浮かぶ石」を 1 つ置き、波が石で反射・回折することで、初画面の空虚さを消し、触るたびに形の変わる干渉縞を生む（IDEAS.md Cycle 12 案A の最小版）。

## 現状（司令塔の評価: 7/10、v12 コミット済み、ヘルス OK）
- 3 秒ルール、泉（長押し）、離しのひと輪、こだま、ムード 3 種は良好。弱点は `shots/cycle-012/desktop-idle.png` の「星屑とヒントだけの空虚な初画面」と、「水が均一で干渉できる物が無い」こと。

## やること（優先順）
1. **石の物理（SIM）。** 状態テクスチャの A チャンネルを「媒質マスク」(0=水, 1=石) として使う。SIM のラプラシアン項を石内部で効かせない（`uK*(1-mask)` 等）、石内部の h・v は毎ステップ 0 へ減衰させ、境界で波が反射・回折するようにする。マスクは `uStone`（x, y, r）で、石を動かした時だけでなく毎 SIM ステップ同じ式で再計算してよい（新規パス・新規テクスチャ・追加フェッチは禁止）。境界は 2〜3 px の smoothstep で柔らかく。
   - 受け入れ条件: 石の左側をタップ→0.8〜1.5 秒後のスクショで、石の右側（影側）の輪が左側より弱く、石の縁で輪が欠けて見える。数値発散（白飛び・画面全体のちらつき）が無い。probe の `eval` でコンソールエラー 0。
2. **石の見た目（RENDER）。** 石の内側は暗いガラス質で、縁にだけ水の光（`uAcc` を少し）と屈折歪みが回り込む。**塗りつぶした円盤・濃い輪郭線・影の落ちた球は禁止**（過去の `.flash` の「泡」失敗の再発防止）。初期位置は画面中心より少し下（スマホで親指が届く位置、バーとヒントに被らない）。半径は短辺の約 7%（最小でも直径 88px 相当）。
   - 受け入れ条件: `desktop-idle.png` と `mobile-idle.png` に石が写り、「ボタン／泡」ではなく「水に浮かぶ暗い石」に見える。ヒント・バー・「響」と重ならない。
3. **石をドラッグで動かす。** 石の半径内の pointerdown のみ石を掴み（通常のタップ／泉は発生させない）、ドラッグで追従、離して止まる。掴んだ時に小さく反応（わずかな波）。石の外側のタップ・長押しは従来どおり（3 秒ルール・泉・離しのひと輪を壊さない）。画面外・バーの下へは出られないよう端でクランプ。
   - 受け入れ条件: probe の `drag` で石を動かすと `dataset.stone`（"x,y" 0–1 の比率）が変わり、動かした後のスクショで石が新位置にあり旧位置にゴーストが残らない。
4. **石の応答音。** 波が石に届く予定時刻（距離÷波速の概算、`setTimeout`）に、`audio.js` の既存 `voice()` を低い周波数・短い減衰で 1 回鳴らす（石は打楽器でなく共鳴体、小さめの音量）。1 タップにつき最大 1 回。ミュート時は鳴らさない。`dataset.stoneHits` を増やす。
   - 受け入れ条件: `?demo=1` で 10 秒後に `dataset.stoneHits >= 1`。
5. **デモの幽霊の指。** 最初のモチーフに「石の手前 → 横 → 石をそっとずらす」を 1 回入れる（石を持つ動きは掴んで離すだけの小さな移動）。`dataset.stones`("1")、`dataset.stone`、`dataset.stoneHits` を出す。
6. **`app/shots.json` の更新。** `idle`/`home` に石が写る。`touched` とは別に新規 `stone-shadow`: `?demo=1` で 1.2 秒待ち→石の左側をタップ→約 1000ms 待って撮影、を desktop/mobile 両方。

## やらないこと
- 石の複数化・消去・レンズ（屈折率の高い石）・石の見た目のバリエーション。
- バーへのボタン追加・説明文の追加。UI は一切増やさない。
- 既存の物理定数（減衰・解像度・`uK` の全体値）の再調整、新規 GL パス、常時 rAF。
- Canvas2D フォールバック (`?fallback=1`) への石の実装（出さなくてよい）。

## 見た目・UX の要求
- デスクトップ 1280×800 / スマホ 390×844 の両方で、石が水面になじみ、バー・ヒントと干渉しない。
- 石を掴める領域は半径＋余裕（最小で直径 88px 相当）。誤って掴んでタップ波紋が出ないこと。
- 石の動きは滑らか（追従に軽い慣性）。Apple 的な静けさを優先し、光り方は控えめに。

## デモモード
カメラ・マイク不要。`?demo=1` だけで石・幽霊の指・石の応答が見える。確認は `dataset.stones/stone/stoneHits` とスクショ（`idle`、`stone-shadow`）。

## 作業役への注意
- **最大のリスクは「石が泡／ボタンに見える」ことと、石の縁での数値発散。** 迷ったら石の縁の光を弱め、境界を柔らかくする。発散する場合は、石内部の減衰を強め、境界幅を広げ、それでも不安定なら「石は固定位置・ドラッグ無し」の最小版に縮めて必ずビルドを通す（壊れたアプリを出さない）。
- 退路: 4（応答音）と 5（幽霊の石ずらし）は、1〜3 が安定してから。時間が無ければ後回しにして REPORT に正直に書く。
- 泉・離しのひと輪・こだま・ムード切替・ミュートの挙動を回帰させない（既存 `shots.json` の画面でスクショ確認）。
- コミットに Claude を貢献者として入れない。`comms/VISION.md` と `comms/STATE.json` は触らない。
