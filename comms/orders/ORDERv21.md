# ORDER v21  (mode: normal)

## 目的
IDEAS.md「Cycle 20 案A 夜光虫」を実装し、**手紙なし・初回訪問の通常画面**に「前と違う絵」（水中の光の点・輪の縁に乗る点線の光・粒の音）を足して、8 サイクル続く 7 点の壁を破る。

## 背景
v20 で提案された 3 案のうち案A を採用済み（IDEAS.md の決定参照）。ヘルスは OK、アプリは v19 から不変。前回出していた repair の ORDER は、撮影が復旧したため取り下げ（この ORDER が置き換える）。`app/shots.json` は待機を既に短縮済みなので、その短縮は維持する。

## やること（優先順）
1. **`glimmer.js` を新規作成し、水中に光の粒を置く。**（GL・シェーダー・テクスチャ読み戻しには触らない）
   - 粒は Canvas2D 1 枚（`#aura` と同じ層の近く、`mix-blend-mode: screen`、`pointer-events: none`）。desktop 48 粒 / mobile（幅 ≤ 600）32 粒、位置はシード固定の疑似乱数（毎回同じ配置、バー・ヒント・「響」の上には置かない）。
   - 静止時の見た目: 半径 1〜2.5px の鋭い点、青白の 1 色（ムードのアクセントから導出）、明るさ 0.12〜0.55、粒ごとに位相をずらしてゆっくり呼吸。`#aura` のボケた粒とは「鋭さ」で区別する。
   - 受け入れ条件: `?demo=1` 起動 1.5 秒の `idle` で、desktop・mobile ともに水中に鋭い淡い点が複数見え、白飛び・雪やゴミに見える明るさ・縁付きの円盤が無い。`dataset.glimmer` = 粒の総数（desktop 48 / mobile 32）。
2. **波に応えて光り、押される。** `tap()`・泉（長押し）・離しの輪から `glimmer.hit(x, y, power)` を呼ぶ。波面の到達時刻 = 距離 ÷ 波速（石・砂州で既に使っている CPU 見積もりと同じ式）で各粒を点灯（約 1.2 秒で減衰）し、外側へわずかに押し、ゆっくり元の位置へ戻す。
   - 受け入れ条件: タップ後 650ms の静止画（`{"clickAt":[640,400]}` → `{"wait":650}` → shot）で、輪の縁に沿って光の点が弧状に並んで瞬いている。`dataset.glints`（点灯した粒の累計）が 1 タップで 3 以上増える。石の影側（石を挟んだ反対側）の粒は点灯を 0.4 秒遅らせる程度の簡易対応でよい。
3. **粒の音。** 点灯した粒が小さな鈴のような粒状の音を鳴らす（粒の横位置の音階音・最高音域・短い減衰、既存 `voice()` または同等の関数を再利用）。
   - 制限（厳守）: 1 タップ最大 6 粒、同時 3 声まで、音量は輪の音の 1/4 以下、輪の最初の音より必ず遅れて鳴る（3 秒ルールの最初の音を邪魔しない）。ミュート時は鳴らさず見た目だけ。
   - 受け入れ条件: `dataset.glintLast`（最後に鳴った粒の x,y）が更新され、`audio=running` のとき `dataset.glints` が増える。コンソールエラー 0。
4. **撮影の証拠整備（小）。** `app/shots.json` に `glimmer-ring`（`/?demo=1` → wait 1200 → `clickAt [640,400]` → wait 650）を追加。`letter-play` は `goto` 直後 600〜900ms で 1 枚、2.5〜3 秒で 1 枚の計 2 枚に直し、手紙の輪とヒント「だれかの水面」が写るようにする。wait の合計は幅あたり 25 秒以下を維持。
   - 受け入れ条件: 撮影が最後まで走り healthy=true。`glimmer-ring` に点線の光、`letter-play` 2 枚目にヒント「だれかの水面」。

## やらないこと
- バー・ヒント・「響」への UI 追加、文言追加、新しいボタン。
- GL シェーダー（`wave-gl.js`）・状態テクスチャの変更、常時 rAF の追加（描画は既存の `wake()` が回っている間だけ。停止中は最後のフレームのまま）。
- 夜光虫の見た目のキャラクター化（魚・虫の絵・目・尾）。光の点だけ。
- 案B（響の字が満ちる）・案C（熱で膜）の先回り実装。
- 外部通信・新規ライブラリ。`VISION.md`・`STATE.json`・`harness/` の編集。

## 見た目・UX の要求
- 粒の明るさ上限 0.55、色は青白 1 色（ムードごとにアクセントから導出し、暁では暖色寄りになってよいが 1 ムード 1 色）。粒は小さく鋭く、まばら。画面全体がキラキラした印象にならず、Apple の壁紙のような静けさを保つ。
- desktop 1280×800 と mobile 390×844 の両方で、粒がバー・ヒント・「響」に重ならず、タップを妨げない。初回の最初のタップで光の輪と音が 3 秒以内に返る既存体験を変えない。
- 輪の縁の点灯は「点線の光が乗る」程度。輪そのものの描画（GL）を隠さない。

## デモモード
- `?demo=1` の幽霊の指の打が `tap()` を通るため、追加の演出なしで粒が光る。確認は `dataset.glimmer` / `dataset.glints` / `dataset.glintLast`。probe 例: `[{"goto":"/?demo=1"},{"wait":1500},{"shot":"idle"},{"eval":"document.body.dataset.glimmer"},{"clickAt":[640,400]},{"wait":650},{"shot":"ring"},{"wait":900},{"eval":"document.body.dataset.glints"}]`。mobile でも同様（`--viewport mobile`、タップ座標は [195,420]）。

## 作業役への注意
- 失敗しやすい点: 粒が「雪／ゴミ」に見える、`#aura` と混ざる、鈴が鳴りすぎてうるさい、石の上や UI の下に粒が出る。上の上限値を守ること。
- 実装後、`?demo=1` で 60 秒放置して `webglcontextlost`・例外が出ず、`wake()` が止まるべき時に止まる（粒が静止中に rAF を回し続けない）ことを確認し、REPORT に書く。
- REPORT には、実行した probe、`dataset` の実測値、見た目の自己評価（粒が汚れに見えないか）を事実で書く。誇張しない。コミットに Claude を貢献者として入れない。
