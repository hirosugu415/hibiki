# ORDER v9  (mode: normal)

## 目的
IDEAS 案C「屈折光の核」を実装し、タップ直後の「白青い塗りつぶし円盤（泡）」を、水に落ちた光の屈折（細い明るい縁＋柔らかい尾）に置き換えて、最初の 1 タップの見た目を Apple 水準の繊細さに引き上げる。

## 現状（司令塔の評価: 6/10 横ばい、ヘルス OK、v8 コミット済み）
- 証拠: `shots/cycle-008/desktop-calm-after.png` の (575,400)・(838,348)、`mobile-touched.png` の (295,470) に、縁のはっきりした塗りつぶしの円盤が写る。周囲の波紋の屈折光と質感が噛み合わず、泡／ボタンに見える。
- `desktop-touched.png` の波紋は、核の光と輪の間に暗い帯が残るドーナツ状。
- 構成: `wave-gl.js` は SIM 1 パス（RGBA16F: 高さ h / 速度 v / 光の滲み glow=b）＋ RENDER 1 パス。RENDER は現在 glow を `hs.b`（中心 1 点）しか使っていない（`add += uAcc * (gl*1.15 + gl*gl*1.4)`）。SIM の glow 注入は `s.w * gs * 1.6`。`main.js` の `flash()`（CSS 円盤、line 105〜125）が `tap()` から呼ばれる。

## やること
1. **まず原因の切り分け（小さく）**: 円盤の硬い縁が、(a) CSS の `.flash`、(b) shader の glow（`gl*gl*1.4` と `knee`）のどちらから来ているかを、`flash()` 呼び出しを一時的に外した probe スクショで確認し、REPORT に 1〜2 行で書く。
   - 受け入れ: REPORT に「円盤の主因は ○○」と、根拠のスクショ名が書かれている。
2. **`flash()`（CSS 円盤）を撤去する**（WebGL2 描画時）。`tap()` からの呼び出し・関連 DOM/Animation を整理し、`.flash` 要素が生成されないこと。Canvas2D フォールバック（`dataset.render !== 'webgl2'`）では従来の `flash()` を残してよい（そのときのみ生成）。
   - 受け入れ: `?demo=1` で 3 秒待った後 `document.querySelectorAll('.flash').length === 0`（eval）。`document.body.dataset.render === 'webgl2'` を確認。
3. **glow を「屈折の縁」として描く（`wave-gl.js` RENDER のみ）**: 既存の勾配用 4 回のフェッチを `.r` だけでなく `.rgb` で受け、glow（b）の勾配 `gg` を得る（**テクスチャ読み取り数は増やさない**）。
   - 塗りつぶしの `gl*1.15 + gl*gl*1.4` の寄与は大きく下げ（中心が白い円盤にならないように）、代わりに `edge`（glow の勾配の大きさに基づく細い明るい縁）と、glow の強い領域で背景を軽くレンズ状に歪ませる項（`q += gg * k`）を加える。
   - 余力があれば、縁の R/B をわずかに半径をずらして出す分散（1 行）。効果が弱ければ入れない。
   - SIM の glow 注入量（`1.6`）・拡散は、見た目に合わせて調整してよい。波の物理（h, v の更新）は変えない。
   - 受け入れ（最重要）: `?demo=1` の起動 1.5〜3 秒後（または `shots.json` の touched 相当）のスクショで、最初のタップ位置に **塗りつぶしの白青い円盤が無く、細い明るい縁と柔らかい尾（光の滲み）が写る**。旧 `desktop-calm-after.png` の (575,400) と同位置を比べ、暗い輪郭・硬い縁が消えていること。デスクトップとスマホ両方。
4. **核と輪の間の暗い帯を「屈折の影」として読める見た目にする**: 暗い抜けに見える場合は、glow の縁の外側に弱い暗部（影）か、逆に淡い連続光を置いて、ドーナツ状の穴が「穴」に見えないよう整える。
   - 受け入れ: `desktop-touched.png` / `mobile-touched.png` で、核→輪の間が自然に繋がって見える（司令塔が見て破綻・白飛び・ちらつきが無い）。
5. **負荷を測る**: 変更前後で `?demo=1` の rAF 間隔（`eval` で `requestAnimationFrame` を 60 フレーム計測した平均 ms など、方法は任意）を REPORT に before/after で書く。
   - 受け入れ: 現行比 +10% 以内。超えたら ALU を削る（分散を外す等）。追加パス・解像度引き上げ・常時 rAF は禁止（`wake()` を維持）。
6. **こだまの光輪（`.echo-ring`）の色を、縁の色と揃える**（`style.css` のみ・少量）。
   - 受け入れ: `desktop-echo.png` で、波紋の縁と戻りの光輪の色が同系統で喧嘩しない。

## やらないこと
- 長押し・持続音・保存・書き出し・新しい UI（案A/B は今回やらない）。バーに何も足さない。
- 追加シェーダーパス、解像度引き上げ、常時 rAF、テクスチャ読み取り数の増加。
- 波の物理（h, v の更新式）の変更。
- 波の輪そのものの形を変える大改造。屈折係数を強くして輪が崩れるなら、係数を下げるか lens 項を外し、「flash 撤去＋縁の細い光」だけの最小版で止める。

## 見た目・UX の要求
- デスクトップ 1280×800・スマホ 390×844 の両方で、タップ直後の光が「水面の中の光」に見えること（UI 部品・泡・ボタンに見えない）。
- 白飛びしない（`knee` を維持）。ヒント・バー・「響」・ムード切替の見た目は変えない（崩さない）。
- 凪・夜・暁の 3 ムードすべてで、縁の色がムードのアクセントに従う（`desktop-mood-night.png` / `desktop-mood-dawn.png` で確認）。

## デモモード
`?demo=1` の幽霊の指だけで確認できること。`shots.json` の既存ステップ（home / touched / echo / mood-* / calm-after / idle）をそのまま使ってよい。タップ直後のスクショが旧版より明確に変わっているかを撮影タイミングで保証すること（glow は約 1.5 秒で消えるため、touched は打鍵直後に撮る）。`?fallback=1` でもコンソールエラーが出ないこと。

## 作業役への注意
- 失敗の再発防止: v2 は「見た目を足して負荷を測らなかった」。必ず手順 5 の計測を REPORT に入れる。
- 係数調整は 1 変数ずつ。輪が崩れる・ちらつく・白飛びしたら、足さずに戻す。
- コミットに Claude を貢献者として入れない。`comms/VISION.md` と `comms/STATE.json` は触らない。
- REPORT には、変更前後で同位置を比べたスクショ名と、`.flash` の本数、rAF 間隔の before/after を必ず書く。
