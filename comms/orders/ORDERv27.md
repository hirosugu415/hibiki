# ORDER v27  (mode: normal)
## 目的
砂の図形を、デスクトップでも「滑らかな丸い砂粒」に見せ、波が通ると砂が**目に見えて**応えるようにする。新機能は足さない。

## やること（優先順）
1. **デスクトップの粒を滑らかに**（`wave-gl.js`）。c26 の「3px セル・半径1px」は dpr1 で 2px 角のドットになり、角張った破片・小さな三角に見える。次のいずれか（または組合せ）で直す:
   セルを 4px・粒半径を 1.3〜1.6px（サブピクセル）にして縁を smoothstep(0.2,1.0) で柔らかくする／粒数を減らして 1 粒を大きく柔らかく／3×3 近傍セルを見てセル境界の欠けを無くす。粒の明るさばらつき・輝度上限 0.5・スマホの静けさ（c26 の見え方）は維持。
   - 受け入れ条件: desktop-plate-high / desktop-touched を画像で開いたとき、線が「角張った破片」でなく、丸くて柔らかい粒の連なりに見える。三角状の欠けが見えない。線の読みやすさ（図形が静止画で分かる）は落とさない。スマホは今以上に密にしない。
2. **波頭で砂が目に見えて応える**。今の +0.15 は見えない。波頭の帯で輝度を最大 +0.35（上限は帯の中だけ 0.6 まで許可）、揺れも 1.5〜2px に強める。追加パス・追加テクスチャ読みは禁止（既に読んでいる g のみ）。
   - 受け入れ条件: desktop-touched で、輪が図形線を横切る箇所の粒が、輪のない所より明らかに明るい／ずれて見える。輪が通り過ぎた後は元に戻る。
3. **shots の修復**（`app/shots.json`）。(a) `desktop-hold`/`mobile-hold`: 通常のタップ後と同じ絵になっており長押しの泉が写っていない。長押しを確実に作る手順（clickAt ではなく drag 同一点や press 保持など、probe で `body[data-holding='1']` を eval で確認できる方法）にし、泉が写ること。(b) `mobile-plate-high`: 図形が消えた後に撮られている。打った直後（1 秒以内）に撮る。待ちの合計は増やさない。
   - 受け入れ条件: hold 画像に泉（長押しの円盤）が見える。mobile-plate-high に図形が見える。
4. （余力があれば）音高を変えたとき、図形が切り替わる瞬間に粒がほどけて再集合する見せ場が既にあるか確認し、無ければ既存の uChl.z（時間差集合）を再利用して切替時に 0 から集め直す。コードが増えすぎるなら省略してよい。

## やらないこと
- バー・ボタン・新 UI・新ライブラリ・図形表の大改造・ムード/石/手紙/「響」の変更。Canvas2D での図形。常時 rAF（減衰して止まる仕様は維持）。

## 見た目・UX の要求
- デスクトップ: 暗地に加算の細い白＋アクセント。粒は丸く柔らかい。輪と砂が同じ世界に見える。
- スマホ 390×844: c26 の静けさを維持。「響」「触れてみてください」・バーが明瞭。親指操作は不変。
- 初回タップで輪と音が 3 秒以内に返る体験は不変。

## デモモード
`?demo=1` で幽霊の指が打つ。probe 例: `[{"goto":"/?demo=1"},{"wait":600},{"clickAt":[1000,400]},{"wait":900},{"shot":"high"},{"eval":"document.body.dataset.plate"}]` を desktop と mobile で。

## 作業役への注意
- 粒の見え方が全て。**dpr1 の desktop 画像を自分で開き、拡大して**角張り・三角の欠けが消えたか確認してから REPORT を書く。改善が見えなければ「未達」と正直に書く（c26 は「完了」としたが画像では未達だった）。
- 波応答は「識別できない」のを繰り返さない。強めて画像で見えることを確認する。
- ビルド・コンソールエラー 0。次サイクルは normal。
