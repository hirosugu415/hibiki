# ORDER v56  (mode: innovation)
## 目的
実装はしない。「響」を 8 点から一段引き上げる、他のアプリにない機能案を 3 つ `comms/IDEAS.md` の末尾に追記する。

## やること
1. `app/NOTES.md` と IDEAS.md の末尾（c52 の提案と決定）を読み、実装済み（雨あがり・空を映す水・奥行きの音・覚える水・水面の残像・石の砂場・初音 など）と重複しない案を 3 つ書く。
   書式は既存の「## Cycle 56 — 提案 (builder)」に合わせる（案名／狙い／体験の流れ／実装規模 S〜M／デモモードでの評価方法／リスクと退路）。
2. 発想の領域（いずれかに寄せる。3 案が同じ領域でなくてよい）:
   - **時間**: 数分〜日単位で水が変わる・育つ体験（ただし評価者が `?demo=1&seed=1` や dataset で数秒に圧縮して確認できること）。
   - **音の質感**: 輪を増やさず、音だけが深く・豊かになる案（c36 の案A「共鳴」の音のみ版など）。
   - **共有・書き出し**: 演奏の結晶（画像・URL・音）を美しく持ち帰る体験。
3. 各案に「静止画 1〜2 枚と dataset 値で白黒がつく受け入れ条件」を必ず添える。

## やらないこと
- app/ のコード変更（NOTES.md を含む）。
- UI の追加や文字の増加を前提にした案。説明が必要な案。
- カメラ・マイク・センサー必須の案（任意の入力としては可）。
- c25/c42 の教訓に反する、波が「筋」「泡」「染み」に見える案。

## 見た目・UX の要求
- 案は desktop・mobile 双方で home の静けさと 3 秒体験を壊さないこと。

## デモモード
- 各案が `?demo=1&seed=1` で評価できる手順を書く。

## 作業役への注意
- 8 点の壁は「面そのものの質」と「体験の再訪性」にある。小さな整合修正ではなく、見て分かる格上がりを狙う案を。
- 実装しないこと。コードを触ると repair になりうる。
