# ORDER v60  (mode: innovation)
## 目的
実装はしない。「響」を 7 点から再び 8 点以上へ引き上げる、他のアプリにない機能案を 3 つ `comms/IDEAS.md` の末尾に追記する。

## やること
1. `app/NOTES.md` と IDEAS.md の末尾（c56 の提案と決定）を読み、実装済み（雨あがり・空を映す水・奥行きの音・覚える水・水面の残像・石の砂場・初音・刻の水 など）と重複しない案を 3 つ書く。
   書式は既存の「## Cycle 60 — 提案 (builder)」に合わせる（案名／狙い／体験の流れ／実装規模 S〜M／デモモードでの評価方法／リスクと退路）。
2. 発想の領域（3 案が同じ領域でなくてよい。c56 と違う軸を優先）:
   - **面の質**: 水面そのものの見え方・光の屈折・波の物理が、見て分かるほど格上がりする案（新しい媒質ではなく、今の水の描画の質を上げる）。
   - **音の質感**: 輪を増やさず、音だけが深く・豊かになる案。
   - **操作の気持ちよさ**: タップ／ドラッグへの応答（触覚・粘り・余韻）が 1 段上がる案。ゼロ UI のまま。
3. 各案に「静止画 1〜2 枚と dataset 値で白黒がつく受け入れ条件」を必ず添える。

## やらないこと
- app/ のコード変更（NOTES.md を含む）。
- UI の追加や文字の増加を前提にした案。説明が必要な案。
- 時刻や空の色味の追加調整（刻の水は完了扱い）。
- カメラ・マイク・センサー必須の案（任意の入力としては可）。
- c25/c42 の教訓に反する、波が「筋」「泡」「染み」に見える案。

## 見た目・UX の要求
- 案は desktop・mobile 双方で home の静けさと 3 秒体験を壊さないこと。

## デモモード
- 各案が `?demo=1&seed=1` で評価できる手順を書く。

## 作業役への注意
- 7 点に下がったのは、3 サイクル連続で色の微調整に使ったため。小さな整合修正ではなく、見て分かる格上がりを狙う案を。
- 実装しないこと。コードを触ると repair になりうる。
