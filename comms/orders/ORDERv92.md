# ORDER v92  (mode: innovation)
## 目的
実装はせず、「響」に足せる他のアプリにない新機能案を3つ `comms/IDEAS.md` の末尾に提案する（見出し: `## Cycle 92 — 提案 (builder)`）。

## やること
1. `app/NOTES.md` と既存の IDEAS.md の末尾（c88 まで）を読み、既に出た案・採用/却下の履歴と重複しない3案を書く。
2. 発想の領域（いずれも「触れる → 音と光の波になる」の核を壊さないこと）:
   - **底の光（caustic）以外**で、初回の1タップ直後に評価者の目に入る新しい驚き（水面・音・光のいずれか）。
   - **再訪・持ち帰り**: 作った音を誰かに渡す／もう一度聴きたくなる仕組み（localStorage のみ、外部送信なし）。
   - **スマホ幅の親指操作**: 傾き・長押し・2本指など、デモモードで再現できる入力の使い方。
3. 各案に必ず書く: 名前 / 体験の一文 / 何が新しいか / 実装規模（S/M/L）/ デモモードでの評価方法（`?demo=1` と shots.json の画面名）/ 最大リスクと撤退条件 / VISION の絶対のルール（初見3秒・説明文なし・Apple 水準）への影響。
4. 最後に「作業役の推し」を1案だけ理由付きで書く。

## やらないこと
app/ のコード変更、UI 追加、ORDER の先取り実装。底の光（caustic）の追加調整案は出さない（c91 で区切った）。既存機能の微調整案も不可。

## 見た目・UX の要求
案ごとに、desktop（1280×800）と mobile（390×844）で静止画として何が見えるかを具体的に書く。文字を増やさず、操作は説明なしで分かること。

## デモモード
カメラ・マイク・センサーが無くても `?demo=1` の幽霊の指だけで評価できる案に限る。評価のための URL パラメータと shots.json 画面名を案ごとに指定する。

## 作業役への注意
- 書くのは IDEAS.md への追記のみ。既存内容は変更しない。
- 新規機能は「ホームの静けさ」を乱さないこと（放置時に何も増えない）。
- NOTES.md は更新不要（コード変更なしのため）。REPORT は事実のみ簡潔に。
