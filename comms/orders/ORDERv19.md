# ORDER v19  (mode: normal)

## 目的
「響の手紙」を**音ごと**渡せるものにして共有の輪を閉じる（受け手は最初のタップで音つき再生、送り手は UI を足さずに渡せる）。

## 現状（司令塔 v18: 7/10、コミット済み `d96de60`、ヘルス OK）
手紙の再生（光だけ）と砂州の可視性は成立した。残る最大の弱点は 2 つ: ① 受け手は自動再生制限のため**無音**で光だけを見る（音と光を結ぶ核が欠ける）、② 送り手が「URL を渡せば演奏が届く」ことを知る・実行する手段が無い。7 点は 10 サイクル横ばい。この 2 点を直して共有体験を完結させる。

## やること（優先順）
1. **手紙を音つきで鳴らし直す（受け手）**
   - `#w=` で起動し、最初の視覚再生が終わった（または中断された）後、**ユーザーの最初の pointerdown（AudioContext が running になる最初の操作）**を契機に、手紙を**音つきで一度だけ**もう一度再生する。ユーザー自身のその 1 打は通常どおり鳴り・輪も出る（取りこぼさない）。手紙の再生はその打の約 0.6 秒後から始める。
   - この「音つき再生」中にユーザーがさらに触れても**中断しない**（今回だけ。ユーザーの打と手紙の打は並行して鳴ってよい）。ただしヒントは再生中「だれかの水面」に差し替える（既存挙動）。
   - 一度音つきで鳴らしたら以後その起動では再生しない。`#w=` が無い・壊れている起動では何も変えない（`dataset.letterPlay` は既存どおり）。`?demo=1` では音つき再演は行わなくてよい。
   - 新しい公開状態: `document.body.dataset.letterVoiced = "0"`（`#w=` ありの起動時）→ 音つき再生が始まったら `"1"`。`#w=` なしでは未設定のまま。
   - 受け入れ条件: probe で `[{"goto":"/#w=PHn_AItg_xSzn_8V"},{"wait":9000},{"eval":"document.body.dataset.letterVoiced"},{"clickAt":[640,200]},{"wait":900},{"shot":"voiced"},{"eval":"document.body.dataset.letterVoiced+'|'+document.body.dataset.letterPlay+'|'+document.body.dataset.audio"},{"wait":7000},{"eval":"document.body.dataset.letterPlay"}]` で、最初の eval が `0`、2 つ目が `1|1|running`（audio が running になっていること）、最後が `0`。スクショ `voiced` で、ユーザーの打の輪と、手紙の最初の打の輪が同時に写る。コンソールエラー 0。`/#w=!!!`・`/`（手紙なし）では `letterVoiced` が未設定で挙動不変。
2. **送り手の導線（UI を足さない）: 「響」をタップして手紙を渡す**
   - 既存のワードマーク「響」（`#wordmark`）を、操作可能にする。**見た目は変えない**（フォント・位置・色そのまま）。ただしタップ領域は 44×44px 以上（透明な当たり判定の拡張で可）、`role="button"`・`aria-label="手紙を渡す"`、キーボード（Enter/Space）でも動く。ホバー／押下で不透明度がわずかに上がる程度の控えめなフィードバック（既存のバーの動きと同質のイージング）。
   - タップ時: 記録が 1 打以上あれば、現在の `location.href`（`#w=` 付き）を、**`navigator.share` が使えてかつ coarse pointer（スマホ）なら共有シート、そうでなければ `navigator.clipboard.writeText`** で渡す。どちらも失敗（拒否・非対応・ヘッドレス）なら何も壊さず、`document.execCommand('copy')` の隠し textarea へフォールバックし、それも失敗なら無言で終わる（エラーを出さない）。共有シートをユーザーが閉じた（AbortError）場合も無言。
   - フィードバック: 既存のヒント要素の文言を 2 秒だけ「手紙を渡しました」に差し替える（成功時）。記録が 0 打なら何もしない（ヒントも変えない）。新しい要素・トースト・ダイアログは足さない。「響」をタップした pointerdown は水面の打としては扱わない（輪を出さない・手紙に記録しない）。
   - 公開状態: `document.body.dataset.letterShare = "0"` → 成功で `"1"`（コピー or 共有が resolve）、失敗で `"fail"`、記録 0 打なら `"none"`。
   - 受け入れ条件: probe で `[{"goto":"/"},{"clickAt":[300,380]},{"wait":300},{"clickAt":[700,300]},{"wait":1200},{"click":"#wordmark"},{"wait":600},{"eval":"document.body.dataset.letterShare+'|'+document.body.dataset.letter"},{"shot":"shared"}]` で `letterShare` が `1` または `fail`（ヘッドレスでクリップボードが拒否される場合を許容。どちらでもコンソールエラー 0）、`letter` は `n=2;…` のまま（「響」タップで打が増えない）。`shared` のスクショで、成功時はヒントが「手紙を渡しました」。mobile (390×844) でも「響」のタップ領域が 44px 以上でバー・ヒントと干渉しない。記録 0 打で「響」をタップしても何も起きない（`letterShare="none"`）。
3. **証拠の補強**: `shots.json` の `letter-play` の wait を 1500 → 900 に変更（ヒント「だれかの水面」が写るように）。追加で `letter-share` ショット（`/` を開き 2 回タップ → 「響」をクリック → 0.6 秒後）を**追加行のみ**で足す。既存の他ショットは変えず、改行コードも変えない。

## やらないこと
- 共有ボタン・シート・ダイアログ・トースト・QR・短縮 URL・署名・有効期限、バーへのアイコン追加。
- 手紙の仕様変更（8 打上限・量子化・記録対象・デバウンス）。ドラッグ・長押し・ムード・石位置の記録。
- 砂州・石・波速・減衰・解像度・拡散係数の変更、追加 GL パス、追加フェッチ、常時 rAF、`readPixels`。
- 新規ライブラリ。外部通信（共有は OS 標準・クリップボードのみ）。
- ワードマークの見た目の変更（サイズ・色・フォント・位置）。

## 見た目・UX の要求
- デスクトップ 1280×800: 初画面は今のまま。「響」はタップできるように見えて**見た目は静か**（ホバーで少し明るくなるだけ）。手紙を開いた直後は視覚再生のみ、最初のタップで音つき再生が重なる。
- スマホ 390×844: 「響」の当たり判定がバー・ヒントと重ならず、親指で届く。ヒント「手紙を渡しました」「だれかの水面」はそれぞれ 1 行・切れない。
- 受け手の体験: 手紙を開く → 3 秒以内に最初の輪（視覚）→ 最初に触れると自分の輪と音 → 少し後に手紙が**音つきで**なぞられる。説明文は出さない。
- 通常起動（`#w=` なし）の体験は変えない。

## デモモード
- `?demo=1`: 従来どおり幽霊の指が演奏（音つき再演は不要）。`?demo=1#w=<値>` でも壊れない。
- 手紙の音つき再生: 上記受け入れ条件の probe（ヘッドレスでは `dataset.audio` が `running` になることとスクショで確認）。
- 渡す動作: probe の `click:"#wordmark"` で `letterShare` を確認（ヘッドレスの失敗は `fail` で許容）。

## 作業役への注意
- 失敗しやすい点: ① 最初の pointerdown でユーザー打と手紙再生が**同じ瞬間**に重なり、AudioContext が running になる前に手紙の最初の打が捨てられる → 手紙は 0.6 秒遅らせ、`audio.unlock()` 後に始める。② 「響」をタップした操作が `window` の capture の pointerdown（`lastTouch`・`audio.unlock`）経由で水面の打として記録される → 「響」上の pointerdown は水面の打・手紙記録から除外（`audio.unlock` 自体は呼んでよい）。③ `navigator.share` はユーザー操作の中でのみ許される → click ハンドラの同期区間内で呼ぶ。④ ヒント差し替えの復元が既存の手紙再生の復元と競合 → 既存の `hintWas`/`hintRestore` の仕組みを再利用し、二重に差し替えない。⑤ 受け手が `#w=` を持ったまま自分でも演奏すると、URL が自分の演奏で上書きされる（既存仕様。変えない）。
- REPORT には、`letterVoiced` の実測値、`audio` の状態、音つき再生で輪が立った位置、`letterShare` の実測値（ヘッドレスで success か fail か）、「響」の当たり判定の実寸（desktop・mobile）を書く。未確認は「未確認」と書く。
- コミットに Claude を貢献者として入れない。`comms/VISION.md`・`comms/STATE.json` は触らない。
