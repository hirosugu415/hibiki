# ORDER v17  (mode: normal)

## 目的
水面に「波を曲げて、遅れて鳴らす」浅瀬＝**砂州**を 1 つ加え、触れて返ってくる応答（屈折・集光・鐘）を、UI を一切足さずに増やす。

## 現状（司令塔 v16: 7/10、コミット済み `986e30a`、ヘルス OK）
石（反射・回折・押される）で「触れる→波→物が動く」は成立。足りないのは演奏の時間的な広がりと、石以外の物理。IDEAS.md の v16 案A（砂州）を採用。

## やること（優先順）
1. **砂州の物理（屈折）**: `wave-gl.js` の SIM に楕円 1 つの uniform（例 `uBar = vec4(cx, cy, rx, ry)`、セル座標）を追加し、楕円内で `uK` を **0.44 → 約 0.26 へ下げる**（境界は 12〜20 セルの smoothstep でぼかす。**上げる方向には決して動かさない**。実効 `uK + 拡散 0.03` は常に 0.47 未満）。追加パス・追加フェッチ無し、状態テクスチャのチャンネル追加も無し。石（A チャンネルのマスク）とは独立。
   - 受け入れ条件: `?demo=1` または probe で砂州の手前（左 25% 付近）をタップし 1.0〜1.8 秒後のスクショで、**輪が砂州の中で遅れて楕円状に歪む**（円でなくなる）こと。画面が発散・白飛び・ちらつきしないこと。コンソールエラー 0。
2. **砂州の見え方（手がかり）**: RENDER に、砂州の位置だけ背景がほんのり明るく見える**縁を持たない低コントラストのうねり**を足す（ベース色への加算は +6% 程度、境界は十分ぼかす、`uAcc`/`uMid` 由来の色で青の世界観を保つ）。**塗りつぶしの円盤・はっきりした輪郭線は禁止**（石・`.flash` が泡に見えた教訓）。
   - 受け入れ条件: `desktop-idle.png` / `mobile-idle.png` で、砂州が「何かある」と気づける程度に淡く見え、汚れ・シミ・泡に見えないこと。石と重ならないこと。バー・「響」・ヒントと干渉しないこと。
3. **潮（ゆっくりした往復）**: 砂州の中心は画面内を約 90 秒周期でゆっくり往復する（例 x が sin で 0.2〜0.8 を移動、y は 0.30〜0.36 付近で固定。石の初期位置 (0.5, 0.6) から離れる軌道）。**位相は rAF が回っている間の dt だけで進める**（静止中に rAF を止める現行の省電力を維持し、再開時に砂州が瞬間移動しないこと。常時 rAF を足さない）。位置は `document.body.dataset.bar = "x,y"`（0〜1 の正規化）で公開。
   - 受け入れ条件: 20 秒以上のデモ起動で `dataset.bar` の x が変化し、常に画面内かつ石の円から外れていること（石とは中心間距離が `石半径＋砂州半径` 以上。近づく場合は砂州の移動を優先せず、鐘だけ抑える）。
4. **鐘（遅れて返る音）**: タップの波が砂州の中心付近に届く頃（石の `stoneEcho` と同じ「距離 ÷ 波速」の CPU 見積もり。砂州内は遅いので 1.4 倍程度の遅延を足す）、砂州が**やわらかい鐘**を 1 回鳴らす。音高は砂州の横位置の音階音（既存の `noteFreq` / `noteIndex`）、音量は小さめ（石の応答音と同程度かそれ以下）、`audio.play` の既存経路を使う。**間隔 0.6 秒以上・1 タップにつき最大 1 回**。GPU 読み戻し（readPixels）は使わない。石の応答音とは別音色・別音高域にして濁らせない（石より 1 オクターブ上など）。累計を `dataset.barChimes` に出す。
   - 受け入れ条件: `?demo=1` で 9 秒待った後 `dataset.barChimes >= 2`。連続タップしても鐘が団子にならない（`barChimes` の増加が 0.6 秒間隔以下にならない）。ミュート中も鐘の呼び出し自体は抑制され、見た目は成立すること。
5. **デモの幽霊の指**: 最初の幕の中で、砂州の手前（砂州の中心から左 25% 付近）を 1 回タップするモチーフを入れる（既存 `ghost.js` のモチーフ列に 1 打足す程度。`firstAct` を壊さない）。
   - 受け入れ条件: `?demo=1` の `home`/`touched` 系ショットのタイミングで、最初の 3 秒ルール（1 タップ → 輪 → 音）が従来どおり成立していること。

## やらないこと
- 砂州のドラッグ移動、複数化、形の変更、複数種の鐘。
- 新しい UI（ボタン・ラベル・ヒント文言の追加）、バーの変更。
- 既存の波速・減衰・解像度・拡散係数の調整（砂州の局所的な `uK` 低下だけが唯一の物理変更）。
- 石の仕様変更・石の復元力の追加（今回は触らない）。
- 追加の GL パス、追加のテクスチャフェッチ、常時 rAF、`readPixels`。
- `shots.json` の全体書き換え・改行コード変更。**追加するショットだけを最小差分で足す**（v15 で 300 行差分が出た再発防止）。

## 見た目・UX の要求
- デスクトップ 1280×800: 初画面は石＋淡い砂州＋星屑。静かで、触れる前から「何かある」が分かるが、主役は石と波のまま。
- スマホ 390×844: 砂州は画面幅比で配置し、石・バー（下）・「響」（左上）と重ならない。親指のタップ位置（下半分）で従来どおり輪と音が返る。
- 色は既存の凪・夜・暁のパレット（`uAcc`/`uMid`/`uDeep`）から導く。ムード切替で砂州も違和感なく色が追従すること。
- Canvas2D フォールバック（`?fallback=1`）では砂州を出さず、鐘も鳴らさなくてよい（`dataset.bar` を出さない）。

## デモモード
- `?demo=1`（幽霊の指が自動演奏）。確認手順: `[{"goto":"/?demo=1"},{"wait":9000},{"eval":"document.body.dataset.barChimes"},{"eval":"document.body.dataset.bar"},{"shot":"a"},{"clickAt":[<砂州の左 25% の x>,<砂州の y>]},{"wait":1400},{"shot":"b"}]`（砂州の位置は `dataset.bar` から求める）。
- `shots.json` に追加するショット名の例: `bar-refract`（砂州の左をタップ → 1.4 秒後）。既存ショットは変えない。

## 作業役への注意
- 失敗しやすい点: ① 砂州内の `uK` 低下で発散 → 0.26 より下げない、実効 0.47 未満を確認。② 淡い帯が汚れ／泡に見える → コントラストは控えめに、境界はぼかす。③ 鐘の連打 → 間隔 0.6 秒・1 タップ 1 回。④ 静止中に砂州が瞬間移動 → 位相は rAF の dt で積算。
- 万一、屈折の見た目が崩れる／不安定な場合の退路: `uK` の低下幅を小さく（0.44 → 0.34）し、明るさのうねりだけ残して、鐘と `dataset` は維持する。壊れたまま出さないこと。
- REPORT には、砂州の `uK` の最終値、`barChimes` の実測値、`dataset.bar` の 2 時点の値、（可能なら）屈折が写ったスクショ名を書く。未確認は「未確認」と書く。
