# ORDER v22  (mode: normal)

## 目的
夜光虫の点灯を「泡」でなく鋭い光の点に整え、**「響」の字が遊んだ量で満ちて手紙の導線を文言なしで示す**（IDEAS 案B）ことで、7 点の壁を破る。

## 背景
v21 評価 7/10（`comms/feedback/FEEDBACKv21.md`）。夜光虫は定着したが変化が繊細で、点灯した粒に丸いハローが付いて泡・ビーズに見える。「響」を押すと手紙が渡せることは依然として見つけにくい。**この ORDER は小さく確実に**。ヘルスが NG になった過去 3 回は撮影の起動失敗なので、`shots.json` の待機は増やさないこと。

## やること（優先順）
1. **点灯した粒の質感を整える**（`glimmer.js`）。
   - 点灯時のハロー（約 14px の淡い丸）をやめる。粒は「鋭い点」のまま、点灯で半径 +0.6px・明るさを上限 0.55 まで上げる程度に。グロー用の半径は点の 2.5 倍以内、不透明度は点の 1/4 以下。
   - 輪の縁の点線の光（sparks）を、輪の GL の位置に近づけて乗せる（現状は輪の内側・外側にばらつく）。簡易でよい: 見積もり半径を波速から出し、± 数 px の揺れに収める。
   - 受け入れ条件: `glimmer-ring` の desktop・mobile で、点灯した粒に縁付きの円盤・泡状のハローが見えず、輪の縁に沿って鋭い点が弧状に並ぶ。`dataset.glimmer` 48/32、`glints` 1 タップで 3 以上は維持。
2. **「響」の字が満ちる（案B・最小版）。**
   - タップごとに `#wordmark` の字が下から淡く満ちていく。0 打=今の無地の淡い白、8 打（`letter` の n と同じ数）=字全体がムードのアクセント色の光で満ちる。`--fill`（0〜1）を CSS 変数で渡し、`background-clip: text` のグラデーション位置で表現する。プログレスバーに見せない（水位は直線でなく、にじみ 1px 以内の波打つ境界）。字の位置・大きさ・フォントは変えない。
   - 8 打に達したら、字は一度だけ小さな鈴の音を鳴らし（既存の `voice()` の鐘、音量は輪の 1/4 以下、ミュート時は鳴らさない）、その後、約 6 秒周期でゆっくり明滅（`opacity` 0.75↔1.0 程度）して「押せる」手がかりになる。「響」を押して手紙を渡したら満ちが 0 に戻る。満ちていない間に押しても今までどおり（何も新しい文言を出さない）。
   - 説明文・ツールチップ・新ボタンは**足さない**。UI は「響」の見た目の変化だけ。
   - 受け入れ条件: `dataset.vessel`（0〜1）が `?demo=1` の最初の 1 秒で 0.2 未満、約 10 秒で 1。`dataset.vesselCall`（0|1）が満ちたら 1。`desktop-vessel-full` と `mobile-vessel-full` の画像で、「響」の字の内側が `home` より明確に明るく／色づいている。字は他の UI と重ならず 390px 幅でも崩れない。
3. **撮影の安定化（小）。** `app/shots.json`:
   - `idle` の `waitFor body[data-stone-laps='2']`（タイムアウト警告が出た）をやめ、`wait` 1500 の 1 枚にする（石の周回に依存しない）。
   - `vessel-full`（`/?demo=1`、`waitFor body[data-vesselcall='1']` を 1 回だけ。5 秒で落ちるなら `wait` 5000 → `waitFor` の 2 段。幅あたりの wait 合計は **25 秒以下**）を追加。`glimmer-ring` と `letter-play-first` は維持。
   - 受け入れ条件: 撮影が最後まで走り healthy=true、step 警告 0。

## やらないこと
- バー・ヒントへの新規 UI・文言追加、新ボタン。
- GL シェーダー・状態テクスチャの変更、常時 rAF の追加（既存の `wake()` が回っている間だけ描く）。
- 手紙の保存形式（`letter.js` のフォーマット）の変更。
- 案C（熱で膜）の先回り実装。外部通信・新規ライブラリ。`VISION.md`・`STATE.json`・`harness/` の編集。

## 見た目・UX の要求
- desktop 1280×800 / mobile 390×844 の両方。満ちた「響」は上品な光で、グローで文字が読めなくならない（Apple のロゴの静かな発光程度）。満ち始め（1 打目）は目立たせず、3 秒ルールの最初の体験を変えない。
- 粒は引き続きまばらで静か。キラキラした印象にしない。

## デモモード
- `?demo=1` の幽霊の指の打が 1.2 秒前後ごとに入るので、約 10 秒で 8 打。確認は `dataset.vessel` / `dataset.vesselCall` / `dataset.glints`。probe 例: `[{"goto":"/?demo=1"},{"wait":800},{"shot":"empty"},{"eval":"document.body.dataset.vessel"},{"wait":5000},{"wait":5000},{"shot":"full"},{"eval":"document.body.dataset.vesselCall"}]`。mobile は `--viewport mobile`。

## 作業役への注意
- 満ちた字が「プログレスバー」や「読み込み中」に見えるのが最大の失敗。字の形そのものが光る表現にする。
- **ORDER を 1 つずつ着実に**。ハロー除去（1）が最小、満ち（2）が主役。2 が難航したら 1 と 3 だけ確実に仕上げて REPORT に書くこと。
- 並走するプロセスで app が書き換えられる事象が v21 で起きた。作業開始時に `git status` で未コミット差分を確認し、REPORT に事実だけ書く。
- 実装後は `?demo=1` で 60 秒放置して例外・`webglcontextlost` が出ないこと、`wake()` が静止時に止まることを確認し REPORT に書く。誇張しない。コミットに Claude を貢献者として入れない。
