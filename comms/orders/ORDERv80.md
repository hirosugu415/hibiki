# ORDER v80  (mode: innovation)
## 目的
実装はしない。泉・bowl・石・雨・空が揃った今、「触れて波が鳴る」の次にある、他のアプリにない体験の案を 3 つ `comms/IDEAS.md` に書く。
## 背景（発想の前提）
- 7 サイクル連続で 8/10。伸びたのは「こすると水が歌う」「双つの泉」のように**静止画 1 枚で新しさが読める**変更だった。微差の調整は評価されない。
- 弱点: (a) mobile 縦画面は画面の大半が空で、模様が小さい・縞が忙しい、(b) 再訪する理由が薄い（前回 76 の案Z「残り灯」は未採用）、(c) 実操作（非デモ）の絵がデモより控えめ。
- 泉・bowl の延長（間隔・振幅・減衰の調整）は完成域。別物の驚きを求める。
## やること
1. 次の 3 領域から**各 1 案**、計 3 案を `comms/IDEAS.md` の末尾に「## Cycle 80 — 提案 (builder)」として**追記**する（既存は変更しない）。
   - 領域X: 静止画で before/after が白黒つく視覚の新現象（花・石・雨・空・泉とは別物。mobile 縦画面を活かす構図を含む）。
   - 領域Y: UI やラベルを増やさず、既存のタップ・ドラッグ・長押し・2 本指の延長で 3 秒以内に発見できる新しい触り方（泉の「2 点を置く」以外）。
   - 領域Z: 再訪したくなる軸（演奏の記録・再生、作品の保存と書き出し、時間経過、前回の痕跡など。localStorage のみ）。
2. 各案に: 一行の名前、体験の説明（ユーザーが何をして何が起きるか）、規模（S/M/L）、デモモード（`?demo=1&seed=1`）での評価方法、`?xxx=0` の退路、最大のリスク。
3. 末尾に「作業役の推し」を 1 つ、理由つきで。
## やらないこと
- app/ の編集、ビルド、NOTES 更新。
- 既存機能（水底・分散・高周波・石・雨・空・収束・bowl・泉）の微調整案。
- UI ボタン・ラベル追加を前提にした案、外部 API・サーバー・ログインを要する案。
## 見た目・UX の要求
- どの案も絶対のルール（説明なし 3 秒、Apple 水準の静けさ）を満たし、desktop・mobile 両幅で成立すること。
- 案Zは過去の失敗（c25/c42 の「泡・塗り円盤」化）を避ける設計であること。
## デモモード
- カメラ・マイク無しで、幽霊の指と URL フック（`?xxx=...&seed=1`）だけで評価可能な案に限る。dataset の状態表示も書く。
## 作業役への注意
- 「静止画 1 枚で差が読めるか」を最重要基準にする。差が読めない案は書かない。
- app/ に触れず、コンソールエラー 0 を保つ。
