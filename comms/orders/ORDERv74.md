# ORDER v74  (mode: normal)
## 目的
bowl（こすると水が歌う）の花を、mobile でも静止画で読める濃さにし、石との重なりと誤検出を解消して仕上げる。
## やること（この順で）
1. **mobile の視認性**: `?demo=1&seed=1&bowl=demo` の mobile-bowl-on で、花のローブ輪郭が desktop-bowl-on と同程度に見えること。半径 R は短辺比のまま、振幅・持続・明暗の出方（屈折の強調ではなく面の明暗）を画面幅に応じて補正する。desktop の見た目は悪化させない。
   - 受け入れ条件: mobile-bowl-on を目視し、ローブが数えられる。
2. **石との重なり回避**: demo の発火中心を石から離す（石の位置が既存の変数で分かるなら、石の影響半径の外に中心と花全体が収まるよう中心を上へ）。ユーザーのこすりで石の近くを使った場合は従来どおり許容。
   - 受け入れ条件: desktop-bowl-on で花の下端が石に触れない。花全体が「響」・ピルと重ならない。
3. **ローブ数を n と一致**: 見えるローブが n 枚になるよう駆動位相を調整する（例: 偶数 n は cos(nθ/2)ではなく、駆動点の位相を n 枚花弁になるよう設計。難しければ n の既定を 3〜4 にして見える枚数を 6〜8 に抑え、dataset.bowl の n は見える枚数を表すよう定義し直す）。花として破綻しない形を優先。
4. **誤検出の確認**: probe で次を確認し、不発であること: 直線ドラッグ、小さな円、1.5 秒かけてゆっくり左右に揺れる往復、タップ連打（同じ場所）。速い往復のみ発火。必要なら閾値（反転間隔・振幅）を調整。結果を REPORT に書く。
5. `app/shots.json` の `bowl-on` は維持。`app/NOTES.md` を更新。
## やらないこと
- 他機能の調整、UI ボタン・ラベル・説明文の追加、guard() の変更。
## 見た目・UX の要求
- 広く柔らかい面の明暗のみ。細い縁線・泡・筋を作らない。home は前回と同一。desktop・mobile 両幅で花が画面内に収まる。
## デモモード
- `?demo=1&seed=1&bowl=demo` で 1.5s 後に発火。`?bowl=0` で従来。カメラ・マイク不要。
## 作業役への注意
- 花の見え方は必ず desktop・mobile 両方の画像を目視してから完了とする。見えなければ形が出るまで調整する。
