# ORDER v3  (mode: repair)

## 目的
v2 で増えた描画コストを下げ、デスクトップ 1280×800 でもフレームが軽くなって、撮影タイムアウト（ヘルス NG）を解消する。見た目は v2 の質を保つ。新機能は禁止。

## 壊れている症状（証拠）
`shots/cycle-002/meta.json` の `reasons`:
- `desktop-home: 画面を開けない/撮れない (page.screenshot: Timeout 5000ms exceeded.)`
- `desktop-touched: …同上`
- `desktop-calm-after: …同上`
ビルドは成功、コンソールエラー 0、mobile 390×844 の 5 枚と desktop の mood 2 枚は撮れている。
司令塔の probe（desktop、約 8.5 秒分の待機）は 31 秒かかり、スクショ1枚が数秒かかった。
v1 は同じ desktop で健全だった。v2 で次を追加したことが原因の最有力候補: レンダーシェーダーの 2 スケール勾配、光の滲みチャンネル、最大 7 ステップ/フレーム、波源キュー。
ヘッドレス Chromium は GPU が無く SwiftShader（ソフトウェア描画）で動くため、ピクセル数×シェーダー負荷がそのまま時間になる。

## やること（優先順位順）
1. **レンダー負荷を下げる（最優先）**。次を組み合わせてよい。
   - キャンバスの内部解像度の上限を決める（例: 長辺 1280px 相当まで。DPR が 2 でも内部ピクセル数が約 1MP を超えないよう、`px` を割る）。CSS で拡大し、見た目は滑らかに保つ。
   - レンダーシェーダーのテクスチャ読み取りを減らす（2 スケール勾配を、重い方のスケールだけ共有・間引く、など）。見た目はほぼ同じに保つ。
   - シミュレーションのステップ数/フレームの上限を 7 から下げる（例: 3〜4）。同時に `STEP_HZ` との整合を取り、波の進む速さが大きく変わらないようにする。
   - **適応品質**: 直近 N フレームの平均フレーム時間を測り、遅い（例: 平均 > 50ms）場合はレンダー解像度のスケールを段階的に下げる（1 → 0.75 → 0.5）。軽くなったら戻さなくてよい（振動防止）。
   - 受け入れ条件: `node harness/tools/probe.mjs` で desktop の `shots.json` 相当（home / touched / mood-night / mood-dawn / calm-after）を撮り、**5 枚とも 5 秒以内にタイムアウトせず撮れる**。probe 全体の所要時間が今回（31 秒）より明確に短くなる。
2. **ヘルスの再確認**: `npm run build` 成功、コンソールエラー 0、desktop と mobile の全 10 枚が撮れること。
   - 受け入れ条件: `shots.json` の全画面が、`probe` の desktop と mobile の両方で撮れている。
3. **見た目の維持を目で確認**: 直したあとのスクショを自分の目で見て、輪が v2 のように柔らかく（細い針金に戻らず）、暁が暖色で、ヒントが読めること。
   - 受け入れ条件: `desktop-home` で暗い空白に明るい輪が 1〜3 個。`mood-dawn` が暖色。ジャギー・ちらつき無し。

## やらないこと
- 新機能、新ムード、UI ボタンの追加、録音/ループ、マイク/カメラ/センサー。
- 外部ライブラリ、ネットワーク、CDN。
- 波動方程式の係数、音（audio.js）の変更。
- 色・パレット・ヒントの再設計（v2 のまま）。

## 見た目・UX の要求
- デスクトップ 1280×800 とスマホ 390×844 で、バー・「響」・ヒントの位置は変えない。
- 解像度を下げる場合も、輪の縁がぼやけてガタつかない（バイリニアで滑らかに）。品質低下が見える段階では下げない（最後の手段だけ）。
- 状態遷移は 200–400ms の ease-out を維持。

## デモモード
`?demo=1` で確認する。幽霊の指の演奏は v2 のままでよい。`calm-after`（9 秒待機）も撮れること。

## 作業役への注意
- 今回の失敗は「見た目を足したのに負荷を測らなかった」こと。変更のたびに probe の所要時間を比べ、REPORT に前後の数字（所要時間、タイムアウト有無）を書く。
- 触っていない主張を REPORT に書かない。
- 余裕があれば（優先度低・必須でない）、タップ直後の輪が多角形に歪む現象（`probe/desktop-d-touch.png` 相当）を、波源の半径/注入量の調整で緩和してよい。ただし 1〜3 を終えてから。
- ビルド失敗・コンソールエラーは即 repair のまま。コミットに Claude を貢献者として入れない。
