# ORDER v1  (mode: normal)

## 目的
VISION「響 (Hibiki)」の最小の核 —— 全画面の水面に触れると、波紋が広がり音が鳴る —— を、Apple 水準の見た目で1画面だけ完璧に成立させる。

## やること（優先順位順）
1. **波の面（コア）**: 全画面（`100dvh`、リサイズ・DPR 追従）の WebGL2 キャンバスで 2D 波動方程式シミュレーション（高さ場＋速度場、減衰あり、縁は柔らかく反射/吸収）を実装し、
   高さ場の勾配から擬似的な屈折・ハイライトを描く（暗い深い青〜紺の水面、波頭がやわらかく光る。白飛び・ジャギー・ちらつき禁止）。
   - 受け入れ条件: タップ/クリック/ドラッグ（pointer events、マルチタッチ可）で触れた位置から滑らかな円形波紋が広がり、複数の波が干渉する。画面外で固まらず、アイドル時に CPU を食い潰さない。
   - フォールバック: WebGL2 または浮動小数点テクスチャが使えない場合でも真っ白/エラーにしない。Canvas2D で同心円の波紋を描く簡易版にフォールバックする（コンソールエラーを出さない）。
2. **音（Web Audio）**: 最初のユーザー操作で AudioContext を開始。触れた位置→音: 横位置=ペンタトニック音階の音高（約2オクターブ）、縦位置=音色の明るさ（上ほど明るい）。
   ベル/マリンバのようなやわらかい減衰音（sine＋少量の倍音、短いアタック、長めのリリース）＋自前生成のコンボリューション/フィードバック・ディレイによる残響。クリックノイズ禁止（ゲインはランプ）。同時発音数に上限（例 12）を設ける。
   - 受け入れ条件: 触れるたびに音が鳴る。ミュート切替が機能する。`document.body.dataset.audio` に `idle`/`running`/`muted`/`unavailable` のいずれかを反映（評価用）。AudioContext が作れなくても例外を出さず波紋だけは動く。
3. **デモモード（幽霊の指）**: `?demo=1` では、ページ読込の約 0.8 秒後から、ゆっくりした自動演奏（ランダムでなく旋律的に聞こえるペンタトニック列、ときどき短いドラッグの軌跡）が始まり、静止画でも常に波紋が見える。
   ユーザーが触れたら幽霊は一旦退く（数秒後に戻る）。通常モードでも、何も触れずに約 8 秒経ったら、控えめに1〜2回だけ幽霊の一滴を落として誘う。
   - 受け入れ条件: `?demo=1` の初回スクショに複数の波紋が映っている。音は AudioContext が suspended でも例外を出さない。
4. **UI クローム（最小・ガラス質）**:
   - 左上に小さなワードマーク「響」（細く、字間・透明度を調整）。初回のみ、画面中央下寄りに薄い一言「触れてみてください」を、最初のタッチで滑らかにフェードアウト（再表示しない。localStorage に記録）。
   - 下部中央に浮くガラス質のコントロールバー（`backdrop-filter: blur`、1px の内側ハイライト、角丸 full、セーフエリア対応）。中身は **ムード切替（3種類）** と **ミュート** のみ。
     ムード: 「凪」（青・ペンタトニック長調）、「夜」（紫紺・短調ペンタトニック、残響長め）、「暁」（琥珀〜桃・長調で明るめ）。切替時は色を約 1 秒でクロスフェードし、音階も変わる。選択は localStorage に保存。
   - アイコンは自作インラインSVG（stroke 1.75、round cap/join、全アイコン同じ線幅とサイズ）。絵文字は使わない。
   - 受け入れ条件: バーが 390px 幅で画面端に触れず、全ボタンのタップ領域が 44px 以上。バーを触っても波紋が誤発火しない（バー上は波紋を出さない）。
5. **撮影設定 `app/shots.json`**: 画面を次の3つ宣言する。(a) `home`（`/?demo=1`、wait 2500）、(b) `touched`（`/?demo=1`、wait 1200 → 画面中央付近を `clickAt` → wait 500）、(c) `mood-night`（`/?demo=1`、ムード「夜」のボタンをクリック → wait 1500）。
   ボタンには安定したセレクタ（例 `#mood-night`、`#mute`）を付ける。
6. **仕上げ**: `<title>` を「響」、`<meta name="theme-color">`、viewport、`color-scheme: dark`、`user-select: none`、`touch-action: none`（キャンバス上）、ページのスクロール・ピンチズーム・iOS のバウンス無効。

## やらないこと
- 録音・ループ、共有・書き出し、設定画面、複数媒質、マイク/カメラ/傾きセンサー入力は **やらない**（次サイクル以降）。
- 外部 API・ネットワーク通信・外部フォント・CDN。npm ライブラリの追加も不要（vanilla で十分）。
- ムードを 3 つより増やさない。UI ボタンを増やさない。

## 見た目・UX の要求
- 配色は深い無彩色寄りの暗色＋ムード色1系統のみ。ムードごとに水面の色・ハイライト色が変わる。ガラスバーは水面の色を透かす。
- タイポグラフィ: `-apple-system, "SF Pro Display", "Hiragino Sans", "Yu Gothic UI", system-ui, sans-serif`。ワードマークは細め、字間広め。文字は少なく、透明度で階層をつける。
- 動き: UI の状態遷移は 200–400ms の ease-out（`cubic-bezier(.2,.8,.2,1)`）。ボタン押下は軽い scale(0.96)。`prefers-reduced-motion` ではクロスフェード以外のアニメを減らす。
- デスクトップ(1280×800): 水面は全面、バーは下部中央で幅 約 280–320px。スマホ(390×844): 同じ構造のまま、親指が届く下部に、セーフエリアを避けて配置。横向きでも崩れないこと。
- 触れた瞬間の応答遅延を感じさせない（pointerdown で即座に波・音を発火）。

## デモモード
`http://localhost:.../?demo=1` で幽霊の指が自動演奏する。ヘッドレスではカメラ・マイクは不要（今回は未使用）。音は聞こえないので、`document.body.dataset.audio` と見た目で確認する。

## 作業役への注意
- 最初のサイクルなので「小さく確実に」。まずビルドが通りコンソールエラーゼロの状態を作り、その上で磨く。真っ白・エラーは即 repair になる。
- WebGL の浮動小数点テクスチャ（`EXT_color_buffer_float` / half-float）の可否を必ずチェックし、フォールバックを用意する。ヘッドレス Chromium（SwiftShader）でも動くこと。
- 完了前に `node harness/tools/probe.mjs` でデスクトップ・スマホ両方を実際に触って確認し、スクショを自分の目で見ること。
- 日本語 UI 文言は短く。コミットに Claude を貢献者として入れない。
