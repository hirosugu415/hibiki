# ORDER v51  (mode: normal)
## 目的
雨のときに水面全体が home より明るく灰みがかる原因を特定して補正し、雨の仕上げを終える。

## やること
1. **背景明度の数値比較（まず証拠）**
   - probe（desktop 1280x800 と mobile）で、`?demo=1&seed=1` の home と `?demo=1&seed=1&rain=1` を同ムード（凪・夜・暁）で撮り、輪から離れた 4 隅＋中央付近（石・輪を避けた数点）の平均輝度を canvas 読み出しか画像解析で比較し、REPORT に表で書く。
   - 受け入れ: 3 ムードの「home 対 rain」の輝度差が数値で REPORT に載る。
2. **原因の補正**
   - 差が出ていれば原因（波の全体エネルギーによる面の持ち上がり、輪の屈折ハイライトの累積、tone mapping、glimmer の加算など）を特定し、**雨のとき（rainLive>0 や rain>0.02 の間）だけ**効く控えめな補正で、輪以外の背景輝度が home の ±5% 以内になるようにする。通常操作（rain 無し）の見た目は変えない。
   - 受け入れ: 補正後の数値が表で ±5% 以内。rain-heavy / rain-night / rain-dawn のスクショで背景が home と同じ深さに見え、輪は消えず静かに見える。通常 shots（rain 無し）は c50 と同一。
   - 差が既に 5% 以内なら「補正なし」と数値で報告してよい（その場合スクショで見える持ち上がりの理由を一文で説明）。
3. **drizzle の輪の周囲のビーズ点（任意・余力があれば）**
   - 輪の周囲の小点が粗く見えるなら強度を僅かに下げる。夜光虫（glimmer）の一部なら触らない。

## やらないこと
- UI・文字・ボタン追加、ライブラリ追加、新しい雨の演出、石・砂・残像・手紙・clearing のロジック変更。

## 見た目・UX の要求
- desktop・mobile とも home は c50 と同一。雨は静かで、白点・糸・ざわつきが出ない。

## デモモード
- `/?demo=1&seed=1&rain=1`（＋ eval でムード切替: `getElementById('mood-night').click()`）。`dataset.rain` / `dataset.weather` で確認。
