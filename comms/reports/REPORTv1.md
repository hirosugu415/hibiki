# REPORT v1  (mode: normal)

## やったこと
1. **波の面（コア）— 完了**: WebGL2 の 2D 波動方程式（高さ+速度、RGBA16F ピンポン、180Hz 固定ステップ、減衰、縁はスポンジ層で柔らかく吸収）。
   高さ勾配から屈折（背景参照位置のずらし）・リム光・スペキュラを描画。白飛びはソフトニー、ディザでバンディング防止。
   pointer events でマルチタッチ・ドラッグ対応。`EXT_color_buffer_float`/`half_float` が無い・FBO 不完全・WebGL2 無しの場合は Canvas2D の同心円波紋に自動フォールバック（`?fallback=1` で強制確認可）。
   最後の入力から約14秒でレンダーループを停止（アイドル時はほぼ CPU/GPU を使わない）。DPR 上限2、リサイズ追従。
2. **音 — 完了**: 最初の pointerdown/keydown で AudioContext 開始。横=ペンタトニック10音（約2オクターブ）、縦=音色の明るさ（ローパス＋倍音量）。
   sine＋倍音2つ、7ms アタック、指数減衰、自前生成IRのコンボルバ（短・長の2系統）＋フィードバックディレイ。同時発音12、超過分は短くフェード。
   ミュート切替あり。`body.dataset.audio` = idle/running/muted/unavailable。AudioContext 失敗時も例外なし。
3. **デモモード — 完了**: `?demo=1` で約0.8秒後に幽霊の指（旋律モチーフ＋ときどきドラッグ軌跡、淡い光の点）。触れると退き、6.5秒後に復帰。
   通常モードは起動時に音なしの小さな一滴、触れずに約8秒で控えめな一滴を2回だけ。
4. **UI クローム — 完了**: 左上「響」（weight 200、字間広め）、初回のみ「触れてみてください」（初タッチでフェード、localStorage に記録）、
   下部中央のガラスバー（blur+saturate、内側ハイライト、角丸 full、セーフエリア対応）に 凪/夜/暁 とミュートのみ。選択インジケータがスライド。
   自作SVGアイコン（stroke 1.75・20px で統一）。ボタンは 76×48 / 48×48（390幅で実測、バー幅305px、左右42pxの余白）。バーは canvas の外なので波紋は誤発火しない。
   ムード切替は約1秒でパレットがクロスフェードし、音階・残響・theme-color・UIのアクセントも変わる。選択は保存。
5. **shots.json — 完了**: home / touched / mood-night（ORDER どおり。`#mood-night`、`#mute` あり）。
6. **仕上げ — 完了**: title「響」、theme-color、viewport（拡大無効）、color-scheme: dark、user-select:none、canvas に touch-action:none、スクロール/バウンス無効。

## 動作確認
- `npm run build` 成功。`probe` でデスクトップ/スマホ両方、WebGL2 と `?fallback=1`（Canvas2D）で操作し、コンソールエラー 0。
- スクショを目視して波紋の太さ・明るさ（最初は太くぼやけていたため、波紋半径と振幅を絞って調整）、3ムードの色、スマホ幅のバー位置を確認。
- クリック後 `dataset.audio` が `running`、ミュート後 `muted`（ヘッドレスなので実音は未確認）。

## デモモード
カメラ/マイク不使用。`?demo=1` で幽霊が自動演奏し、静止画でも常に複数の波紋が映る。ユーザー操作前は AudioContext を作らないため `dataset.audio=idle`（警告なし）、最初のタッチ以降に幽霊の音も鳴る。

## 既知の問題・妥協点
- 実際の音の聴感（音量バランス・リバーブ量）は聞いて確認できていない。コードと状態のみ検証。
- ドラッグ時の音は音階セルを跨ぐたび（110ms スロットル）に鳴る簡易実装。
- 解像度の低いスマホでの実機 fps は未測定（シミュ格子は長辺420セル固定で軽量のはず）。
- WebGL コンテキスト喪失の復帰は resize 発火に頼る簡易対応。
- 画面全体はやや暗め。波紋の「煌めき」の質感はまだ伸びしろあり。
