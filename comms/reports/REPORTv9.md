1. 原因の切り分け — **完了**。`.flash` を CSS で非表示にして撮った `shots/cycle-009/probe/desktop-before-noflash-150.png` でも、同じ縁つきの円盤が残った（`desktop-tap-150.png` の旧版と同形）。
   さらに現行コードでは `.flash` は 0 本。**円盤の主因はシェーダー（RENDER）**。内訳は 2 つ:
   (a) glow を `gl*1.15 + gl*gl*1.4` で塗りつぶしていた、(b) 打鍵直後の高振幅の隆起（rim/spec/hp 項）が飽和して核の周りを埋めていた。

2. `flash()` 撤去 — **完了（WebGL2 時のみ）**。`tap()` は `backend.kind !== 'webgl2'` のときだけ `flash()` を呼ぶ。
   `?demo=1` で 3 秒待ち後 `.flash` = 0、`dataset.render === 'webgl2'`（eval 確認）。`?demo=1&fallback=1`（Canvas2D）では従来どおり生成され（flash=2）、コンソールエラー 0。
3. glow を屈折の縁として描く — **完了**。既存 4 回のフェッチを `.rgb` で受け、glow の勾配 `gg` を取得（読み取り回数は 5 のまま）。
   - 塗りつぶし項を撤去し、`edge`（glow の等値線 gl≈0.2 の付近だけを、勾配が立っている所で細く光らせる）＋ 弱い尾（`gl*0.22`）に置換。
   - 打鍵直後の核（glow が強い所）では波の隆起の rim/spec/hp を `fresh` で抑え、波が広がるにつれ通常描画へ戻す。
   - rim の飽和をなだらかに圧縮（`slope/(1+0.9*slope)`）。小さな波の見え方はほぼ不変。
   - レンズ歪み項（`gg*LENS`）は実装したが **LENS=0 で止めた**（輪が崩れる恐れ、ORDER の「効果が弱ければ入れない」に従い最小版）。分散（R/B ずらし）は入れていない。
   - SIM の glow 注入量・拡散は変更なし。波の物理（h, v）は不変。
   - 比較スクショ: 旧 `desktop-tap-150.png`（作業前・円盤）→ 新 `desktop-a.png` / `desktop-b.png` / `mobile-m-tap.png`。新版は塗りつぶしが無く、細い明るい輪＋柔らかい外側の光。

## 既知の問題・妥協点
- ヘッドレスは描画が遅く、「打鍵後 N ms」のスクショは実際のフレーム数がぶれる。touched のスクショは、微妙に毎回違う位相になる。
- 打鍵直後は、輪の外側に暗い線が 1 本ある。完全に消してはいない。
- 実機の見え方（60fps 時の glow の流れ）はヘッドレスでは確認できない。
- 定数は `wave-gl.js` 先頭の `#define`（EDGE_* / TAIL* / CORE* / FRESH）で調整できる。
