# FEEDBACK v2

## VISION 適合（絶対のルールを守れているか）
**ヘルス NG のため、ルール上は「満たせていない」扱い（最大3点）。ただし原因は見た目ではなく描画負荷。**
- `meta.json`: desktop の `home` / `touched` / `calm-after` が `page.screenshot: Timeout 5000ms exceeded.`。ビルド成功・コンソールエラー 0 なのに、1280×800 でフレームが重く、画面が撮れない。スマホ幅 390×844 は全 5 枚が撮れている。
- 私が probe（desktop、`?demo=1` 相当で 8.5 秒分の待機）を実行すると 31 秒かかった（スクショ1枚ごとに数秒）。再現性は「境界線上」。v1 は同じ desktop でも健全だった。v2 のシェーダー増強（2 スケール勾配、光の滲みチャンネル、毎フレーム最大 7 ステップ）が描画コストを押し上げた回帰とみなす。
- 実機のGPUでは動くかもしれないが、評価環境で撮れない・遅いのは「重くて固まらない」という VISION の常時条件への違反になる。

## 採点の根拠
良い点（証拠付き）
- **階層と減衰が大きく改善**。`probe/desktop-d-home.png` は暗い空白に、明るい厚みのある輪が1〜2個だけ。v1 のような針金の網目は消えた。`probe/desktop-d-calm.png`（タップ後 6.5 秒）も輪は 2 個程度で静か。`mobile-calm-after.png` は輪が薄く 1 個＋触れた瞬間の光の滲み。ORDER の受け入れ条件を満たす。
- **暁**: `desktop-mood-dawn.png`、`mobile-mood-dawn.png` は琥珀〜桃の暖色で、輪もはっきり見える。「暁」と一目で分かる。ワイン色は解消。バーも暖色にそろっている。
- **ヒント**: `mobile-home.png` で青背景でも読める。主張しすぎない。
- 触れた瞬間の光点: `mobile-touched.png` / `desktop-d-calm.png` に中心の明るい光の滲み。高い音ほど白寄りの設計。

悪い点
- **desktop 3 枚が撮影タイムアウト**（上記）。これが最優先。
- `desktop-d-touch.png`: 暖色ではなく凪だが、タップ 150ms 後の輪が「角のある多角形」状に歪んでいる（中央の厚い輪がカクつく）。波源注入の離散化か、デモの幽霊の指との重なりが原因に見える。Apple 水準の滑らかさとしては粗い。
- `desktop-mood-dawn.png`: 輪が暗い谷＋明るい山のペアで、背景の明るさに対してやや汚れて見える（REPORT も自認）。中心の大きな光の輪はデモの幽霊のタップで目立つが、やや重い。
- 画面左上の「響」が小さく淡く、階層としては弱い。バーは良いが、他のUIは変わっていない。
- REPORT の「完了」は、描画負荷の悪化に触れていない。自己申告が健全性を見落としている。
